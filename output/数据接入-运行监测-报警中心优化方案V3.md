# 数据接入、运行监测、报警中心优化方案 V3

> 依据：2026-09-17 council 式产品评审结论  
> 范围：设备管理系统标准版前端演示  
> 结论：不做一次性大包改造；按“数据事实一致性 → 报警语义 → 规则状态化 → 跨页面一致性”四批实施。

## 1. 修订后的总原则

1. **先修事实，再修文案。** 页面提示可以晚一步统一，但状态、数据来源、报警事件、OEE 口径不能互相矛盾。
2. **演示能力不等于真实接入能力。** 不新增真实 IoT、协议、网关、鉴权功能；只保证演示状态机内部自洽。
3. **保留现有模块边界。** 不删除点检、保养、巡检页面，不删除 OEE，不把宿主平台承接的权限/审计纳入本方案。
4. **每个批次必须有 reducer 级验收。** UI 只作为补充检查，不作为主要验证依据。

## 2. 实施批次

### P0-A 数据事实与绑定一致性

**目标：保证设备、绑定、实时样本、OEE 使用同一套来源事实。**

| 编号 | 优化项 | 方案口径 |
|---|---|---|
| A1 | 实时样本按来源匹配 | `selectRealtime` 的样本匹配键从 `deviceId + metricCode` 调整为绑定项的 `iotDeviceCode/sourceId + metricCode`。设备层只负责展示，不承担样本归属判断。 |
| A2 | 绑定启用重校验来源占用 | `binding/enable` 前重新计算其它设备的启用来源集合，出现占用即拒绝启用，不允许绕过草稿校验。 |
| A3 | 补齐换绑流程 | 建立原绑定、目标来源、指标映射、生效时间四要素。换绑期间新旧来源不得同时作为有效实时数据。 |
| A4 | 断连与停用降级 | 绑定停用或来源断连时，实时值、采集时间、状态均显示 `--` 或明确降级态；不得沿用旧样本造成“运行中”的假象。 |
| A5 | OEE 不可计算口径 | 数据不可用时 OEE 显示 `--`，状态为“不可计算”，并给出原因。禁止同时展示数值和“不可计算”。 |
| A6 | 刷新语义 | `lastSampleAt` 只代表真实样本时间。断连时刷新动作不得推进 `lastSampleAt`，只记录接收/刷新时间。 |

**验收用例**

- 两台设备配置同名指标，但来源不同，展示值互不影响。
- 来源 A 已被设备 1 启用，设备 2 尝试启用来源 A 被拒绝。
- 设备换绑后，实时页只读取新来源样本，历史统计仍保留旧来源事实。
- 绑定停用后，运行监测显示数据中断，OEE 显示 `--`。
- 断连后连续刷新，最后样本时间不变。

### P0-B 报警事件语义

**目标：恢复、关闭、重复触发有明确边界，报警不再吞事件。**

| 编号 | 优化项 | 方案口径 |
|---|---|---|
| B1 | 事件实例化 | 去重只作用于“活动事件”。同一设备、规则版本、绑定版本存在未关闭事件时合并计数；一旦关闭，再次触发生成新事件。 |
| B2 | 自动恢复条件化 | 无业务关联的自动恢复规则，可在恢复后自动关闭；关联工单、停机或人工处置链路的报警，只能进入“已恢复待关闭”，必须通过关闭校验。 |
| B3 | 关闭校验统一 | 所有关闭入口统一使用 `closeBlockers`。工单未验收、停机未结束、缺少关闭原因时不得关闭。 |
| B4 | 报警中心列表口径 | 活动事件合并展示计数；历史事件按事件实例展示，不允许历史 dedupeKey 吞掉新事件。 |
| B5 | 恢复证据 | 自动恢复需记录恢复时样本值、来源时间、规则版本、绑定版本；不得只写“指标恢复”。 |

**验收用例**

- 同一报警连续触发 3 次，列表展示 1 条活动事件，触发次数为 3。
- 关闭后再次触发，生成新报警事件，旧事件保留在历史。
- 温度已恢复正常，但工单待派工时，报警不得关闭。
- 工单验收通过且停机结束后，报警恢复并关闭。
- 自动恢复类报警无业务关联时，恢复后自动关闭。

### P0-C 规则配置状态化

**目标：规则配置成为报警触发的唯一事实来源，旧种子仅作初始快照。**

| 编号 | 优化项 | 方案口径 |
|---|---|---|
| C1 | 规则进入 DemoStore | 建立 `rulesByCode`、`ruleVersionsById`、规则历史。启用、停用、草稿、发布、版本回滚全部走 reducer。 |
| C2 | 状态机 | 草稿 → 校验中 → 校验通过 → 已发布；已发布 → 已停用；已停用 → 草稿。未发布规则不得触发报警。 |
| C3 | 版本影响范围 | 规则变更记录设备范围、绑定版本、生效时间、影响模块。触发报警时写明规则版本和绑定版本。 |
| C4 | 模板能力 | 模板应用到草稿，不直接发布；草稿确认后才生成规则版本。 |
| C5 | UI 提示 | “保存草稿”、“发布”、“停用”分别给出真实动作结果；禁止无状态变化的假成功提示。 |

**验收用例**

- 保存草稿不产生已发布规则。
- 停用后规则不再触发新报警。
- 发布新版本后，新事件带新版本号。
- 规则版本历史可追溯启用、停用、发布时间。

### P1 跨页面一致性

| 编号 | 优化项 | 方案口径 |
|---|---|---|
| D1 | 程序比对明细键 | 详情数据按 `recordId` 关联，不允许两台设备共享同一套实际参数。 |
| D2 | 程序比对状态 | “一致”、“参数不一致”、“比对失败”、“不适用”分别绑定明确数据状态与原因。 |
| D3 | 处理闭环 | 比对处理记录与报警、维修工单关联时，状态变化需双向可见。 |
| D4 | 大屏数据源 | 短期明确标注“演示数据”；中期复用 DemoStore，确保设备数量、时间、状态与主应用一致。 |

**验收用例**

- 两台设备使用同一程序版本，详情展示各自实际值。
- DEV-001 显示“一致”时，展开明细不得出现超容差项。
- 大屏与实时页的设备数、运行状态、报警数量一致。

## 3. 关键设计调整

### 3.1 样本归属

样本必须同时具备：

- `deviceId`：业务设备。
- `sourceId`：IoT 来源。
- `metricCode`：指标编码。
- `sourceTime`：采集时间。
- `receiveTime`：接收时间。
- `qualityCode`：质量码。

展示层只允许通过当前有效绑定映射取值，不得直接按 `deviceId + metricCode` 全局查找。

### 3.2 报警去重

`dedupeKey = deviceId:ruleCode:ruleVersion:bindingVersion` 仍然保留，但仅用于活动事件合并。事件关闭后，键不再阻断新事件生成。

### 3.3 规则状态

规则配置不再读 `ruleRows`、`netBindings` 作为交互事实。DemoStore 初始化时可导入旧数据，但之后的变更必须通过 action/reducer 完成。

## 4. 依赖与风险

| 风险 | 处理 |
|---|---|
| 样本结构变化影响多个页面 | 先在 selector 层集中调整，页面保持调用不变。 |
| 规则迁移影响 84 路由烟测 | P0-C 单独成批，完成后全量跑 `node check-pages.cjs`。 |
| 报警历史兼容 | 不迁移历史数据语义；只保证新触发事件按新口径生成。 |
| 大屏独立 HTML | P1 只做标注或复用数据，不与 P0 混批。 |

## 5. 验证流程

1. 每批完成后运行 `npm run build`。
2. 每批完成后运行 `node check-pages.cjs`，要求 84 路由 0 空白、0 JS 错误。
3. P0-A、P0-B、P0-C 增加 reducer 级场景测试，覆盖表格中的验收用例。
4. 程序比对增加双设备同程序版本的实际值独立展示测试。

## 6. 不做事项

- 不实现真实 MQTT、WebSocket、协议网关、IP、端口、点表编辑。
- 不接入真实权限、审计、后端。
- 不删除点检、保养、巡检页面。
- 不在 P0 阶段重做大屏视觉。
