# 设备全生命周期管理功能设计方案

> 版本：V1.2（当前执行版）  
> 修订日期：2026-09-18  
> 适用产品：东浩智创设备管理系统标准版  
> 文档状态：可用于产品评审、原型设计和开发拆分  
> 关联参考：[设备全生命周期管理功能设计文档-V1.1-简化流程版](./设备全生命周期管理功能设计文档-V1.1-简化流程版.md)

## 1. 方案结论

本次迭代不在设备管理系统内建设完整采购、到货、安装、调试和独立技术验收模块，而是建设一个轻量、可追溯的设备生命周期业务域。

系统主流程如下：

```text
采购入账
  → 使用部门试用确认
      ├─ 合格 → 设备办理手续入账
      └─ 不合格 → 退回采购
```

其中：

- 采购订单、供应商、合同、物料和采购执行由 SRM/采购系统负责。
- WMS 可以提供设备类物料的收货或到货信息，设备管理系统也允许手工新增采购入账。
- WMS/SRM/手工数据均进入同一个“采购入账”任务，不新增“到货记录”独立菜单和独立审批。
- 使用部门只做试用确认，不建设安装、调试、试运行或独立技术验收页面。
- 试用合格后，由设备管理员上传验收单、设备档案并补全台账，生成设备编码/资产卡片。
- 设备建档后进入现有的监测、报警、OEE、维修、备件、点检、保养和巡检模块。
- 设备变更、闲置、报废按照附件保留范围建设，红线划掉的功能不做。

## 2. 建设目标

### 2.1 业务目标

1. 让新设备从采购完成到正式纳入设备台账有明确入口。
2. 用使用部门试用结果作为设备是否继续办理入账的业务门槛。
3. 将验收单、设备档案、合同和试用意见统一关联到设备及流程任务。
4. 让调拨、改造、借用、外送、闲置、再启用和报废形成受控单据。
5. 保证设备状态变化有审批、有前后快照、有操作履历。
6. 避免在设备管理系统重复建设 SRM、WMS、ERP 已经负责的业务。

### 2.2 产品目标

- 用一个统一生命周期任务承载主流程。
- 用设备台账作为正式资产信息的唯一展示入口。
- 用设备详情的生命周期履历记录全过程。
- 用工作台集中展示待办、退回、超期和异常。
- 采用“动作 + 前置校验 + 状态迁移 + 审计事件”的方式修改业务事实。

### 2.3 非目标

以下内容不属于本方案建设范围：

- 采购申请、询价比价、采购订单、付款、供应商结算。
- WMS 仓库收货、库位、库存和出入库作业。
- 独立到货记录、到货核验、开箱检查和入厂登记页面。
- 安装管理、调试管理、试运行项目和厂家施工管理。
- 独立技术验收、条件通过和复验流程。
- 报废后的拆除、出售、回收、运输、环保联单和处置执行。
- 财务会计凭证、折旧计算和固定资产核销本体。
- 真实 IoT 协议、网关、采集点表和后端数据采集。
- 删除或替代既有点检、保养、巡检、维修、备件、OEE 功能。

## 3. 系统边界和数据来源

### 3.1 系统职责分工

| 系统 | 负责内容 | 本系统处理方式 |
|---|---|---|
| SRM/采购系统 | 物料、供应商、采购订单、合同、采购收货事实 | 带入采购入账，保存外部引用和必要快照 |
| WMS | 仓库实际收货、数量、批次、库位和交接 | 可作为采购入账来源，不建设重复收货流程 |
| 设备管理系统 | 采购入账、试用确认、设备手续入账、设备台账、变更、闲置、报废履历 | 本方案核心建设范围 |
| ERP/财务系统 | 原值、资本化、折旧、财务核销 | 通过外部引用或人工回填，不在本系统核算 |
| 宿主平台/OA | 组织、人员、权限、统一审批、消息 | 复用平台能力，本系统提供业务节点和业务规则 |
| 现有运行模块 | 监测、报警、OEE、维修、备件、点检、保养、巡检 | 设备入账后按状态和资格联动 |

### 3.2 采购入账数据来源

采购入账支持三种来源：

| 来源 | 适用场景 | 规则 |
|---|---|---|
| SRM/采购系统 | 有采购订单、合同和供应商数据 | 自动带入采购事实，外部编号只读 |
| WMS | 设备经过仓库或 WMS 已形成收货记录 | 收货信息用于预填和追溯，不生成独立到货任务 |
| 设备管理系统手工新增 | 直送现场、接口未覆盖、历史补录或临时业务 | 必须填写来源说明和创建人，必要时补录外部单号 |

三种来源进入同一张采购入账单，使用同一套提交、退回、试用确认和入账规则。来源不是业务分支，不允许形成三套不同流程。

### 3.3 外部接口最小字段

当 SRM/WMS 向本系统推送时，建议至少提供：

- 来源系统 `sourceSystem`
- 外部单据号 `sourceReceiptId` 或采购订单号
- 外部单据行号 `sourceLineId`
- 物料编码、物料名称、物料分类
- 设备类标识 `assetizationFlag`
- 型号、品牌、规格
- 供应商
- 收货数量、单位、收货时间
- 发货时间（采购系统可提供时）
- 合同号、合同附件引用
- 批次号、序列号（有则带入）
- 原始附件引用和来源版本

外部数据只读保留，后续补充信息在本系统形成业务字段，不覆盖原始来源事实。

## 5. 主流程设计

### 5.1 流程图

```text
采购入账草稿
      ↓ 提交
使用部门试用确认中
      ├─ 提交合格
      │      ↓
      │  待设备手续入账
      │      ↓
      │  设备已入账
      │
      └─ 提交不合格
             ↓
        退回采购
             ↓
      修改/补充/更换后重新提交
```

### 5.2 流程状态

| 状态 | 状态编码 | 说明 |
|---|---|---|
| 草稿 | `DRAFT` | 采购入账尚未提交 |
| 试用确认中 | `TRIAL_PENDING` | 已提交，等待使用部门确认 |
| 试用不合格退回 | `TRIAL_REJECTED` | 退回采购补充或更换 |
| 待设备手续入账 | `REGISTRATION_PENDING` | 试用合格，等待设备管理员 |
| 设备手续入账中 | `REGISTRATION_EDITING` | 正在补全台账和上传附件 |
| 设备已入账 | `REGISTERED` | 台账已生成，主流程完成 |
| 已撤回 | `WITHDRAWN` | 提交人主动撤回，保留记录 |
| 已取消 | `CANCELLED` | 经授权取消，必须填写原因 |

### 5.3 流程迁移规则

| 当前状态 | 动作 | 目标状态 | 允许角色 |
|---|---|---|---|
| 草稿 | 提交试用 | 试用确认中 | 采购人员 |
| 试用确认中 | 提交合格 | 待设备手续入账 | 使用部门试用负责人 |
| 试用确认中 | 提交不合格 | 试用不合格退回 | 使用部门试用负责人 |
| 试用不合格退回 | 重新提交 | 试用确认中 | 采购人员 |
| 待设备手续入账 | 开始办理 | 设备手续入账中 | 设备管理员 |
| 设备手续入账中 | 提交入账 | 设备已入账 | 设备管理员 |
| 草稿/试用确认中 | 撤回 | 已撤回 | 发起人或授权管理员 |

任何状态迁移都必须经过动作校验，不允许页面直接修改状态字段。

## 6. 功能设计

## 6.1 生命周期工作台

### 功能目标

为各角色提供统一待办入口，集中展示主流程和资产治理事项。

### 指标卡

- 待提交采购入账
- 待试用确认
- 试用不合格退回
- 待设备手续入账
- 待补充台账资料
- 待处理资产变更
- 待复核闲置设备
- 待技术鉴定报废
- 待财务核销/归档

### 任务列表

| 字段 | 说明 |
|---|---|
| 任务号 | 生命周期任务唯一编号 |
| 业务类型 | 采购入账、试用确认、设备手续入账、变更、闲置、报废 |
| 当前节点 | 当前待处理节点 |
| 设备信息 | 设备名称、型号、品牌、数量 |
| 使用部门 | 申请或使用组织 |
| 当前处理人 | 指定人或候选角色 |
| 状态 | 业务状态 |
| 创建时间 | 单据创建时间 |
| 截止时间 | 按配置计算 |
| 异常提示 | 资料缺失、退回原因、接口待对账等 |
| 操作 | 处理、查看、催办、撤回 |

工作台不得显示已取消的到货、安装、调试、验收节点。

## 6.2 生命周期流程任务

### 功能目标

统一管理采购入账、试用确认、设备手续入账三个节点，使一个批次或一项设备从开始到入账始终关联同一任务。

### 列表筛选

- 任务号
- 设备名称/型号
- 采购订单号/合同号
- 来源系统
- 使用部门
- 当前节点
- 业务状态
- 创建时间
- 处理人
- 是否退回

### 任务详情

任务详情采用“基本信息、节点信息、附件、流程轨迹、关联设备、操作记录”六个区域。

### 批量设备规则

采购入账可以填写数量。设备手续入账时：

- 同型号、同批次、同责任部门的设备可以批量建档。
- 需要独立序列号、二维码或资产编号的设备必须逐台补录。
- 一条任务可以关联多个设备台账。
- 任何设备未完成入账时，任务可显示“部分完成”。
- 任务全部关联设备完成后，状态改为“设备已入账”。

## 6.3 采购入账

### 页面用途

采购人员登记需要纳入设备管理的采购设备，提交使用部门试用确认。该页面不承担采购下单、收货、付款或库存管理。

### 表单字段

| 分组 | 字段 | 必填 | 来源/规则 |
|---|---|---:|---|
| 来源 | 来源类型 | 是 | SRM、WMS、手工 |
| 来源 | 外部单据号 | 条件必填 | 系统同步时只读；手工可后补 |
| 来源 | 采购订单号 | 否 | 可从 SRM 带入 |
| 设备 | 设备名称 | 是 | 设备名称 |
| 设备 | 型号/规格 | 是 | 型号或规格 |
| 设备 | 数量 | 是 | 正整数，大于 0 |
| 设备 | 品牌 | 是 | 品牌名称 |
| 采购 | 供应商 | 否 | 可从采购系统带入 |
| 采购 | 发货时间 | 是 | 供应商发货时间 |
| 采购 | 合同号 | 是 | 合同编号 |
| 采购 | 合同附件 | 按配置 | 合同扫描件或引用 |
| 采购 | 采购金额 | 否 | 有则带入，不在本系统核算 |
| 组织 | 使用部门 | 是 | 后续试用部门 |
| 组织 | 试用负责人 | 是 | 试用任务处理人 |
| 其他 | 备注 | 否 | 采购说明 |
| 附件 | 订单/发货凭证 | 否 | 支持多附件 |

### 操作

- 保存草稿
- 提交试用确认
- 撤回
- 修改
- 查看退回原因
- 查看流程轨迹

### 提交校验

1. 设备名称、型号、数量、品牌、发货时间、合同号和使用部门不能为空。
2. 数量必须为正整数。
3. 手工新增必须填写来源说明和创建人。
4. 外部同步记录必须保存来源系统和外部单据号。
5. 合同附件是否必传由系统配置；不传时需要填写例外原因。
6. 提交后采购核心字段只读，需撤回或退回后修改。

### 手工新增规则

手工新增不是独立流程，只是采购入账的一种来源：

- 标记 `sourceType=MANUAL`。
- 记录新增人、新增时间和来源说明。
- 有采购订单或 WMS 收货单时必须关联。
- 无外部单号时必须填写例外原因和后续补录责任人。
- 在设备正式入账前完成外部单号补录或采购/设备管理员复核。

## 6.4 使用部门试用确认

### 页面用途

使用部门根据实际使用情况判断设备是否满足使用要求。该页面只保留简单结论，不扩展调试、技术验收或试运行项目。

### 表单字段

| 字段 | 必填 | 规则 |
|---|---:|---|
| 试用结论 | 是 | 合格/不合格 |
| 试用开始时间 | 否 | 实际试用时间 |
| 试用结束时间 | 否 | 实际试用时间 |
| 使用部门意见 | 是 | 适用性和使用感受 |
| 主要问题 | 不合格时必填 | 说明缺陷或不满足项 |
| 退回建议 | 不合格时必填 | 退回、更换、补充资料等 |
| 试用照片/记录 | 否 | 支持图片或文件 |
| 确认人 | 系统带入 | 当前处理人 |
| 确认时间 | 系统带入 | 提交时记录 |

### 操作

- 保存草稿
- 提交合格
- 提交不合格并退回采购
- 查看采购入账信息
- 查看历史试用记录

### 业务规则

1. 选择“合格”后，任务进入“待设备手续入账”。
2. 选择“不合格”时，主要问题和退回建议必须填写。
3. 不合格退回保留原采购信息、试用意见和附件。
4. 采购补充、更换或修正后，可以重新提交同一任务。
5. 每次重新试用生成新的试用记录，不覆盖原记录。
6. 试用不合格设备不得生成正式设备台账，不得进入正式 OEE 和在用设备清单。

## 6.5 设备办理手续入账

### 页面用途

设备管理员对试用合格设备办理正式入账手续，上传验收单和设备档案，补全设备台账。

### 表单字段

| 分组 | 字段 | 必填 | 说明 |
|---|---|---:|---|
| 关联 | 生命周期任务号 | 是 | 必须关联试用合格任务 |
| 资产 | 设备编码 | 系统生成 | 按编号规则生成，可按权限调整 |
| 资产 | 资产编号 | 按规则 | 可由财务系统回传 |
| 设备 | 设备名称 | 是 | 从采购入账带入 |
| 设备 | 型号/规格 | 是 | 从采购入账带入，可补充 |
| 设备 | 品牌 | 是 | 从采购入账带入 |
| 设备 | 制造商 | 否 | 设备制造厂商 |
| 设备 | 序列号/制造号 | 按设备类型 | 需要逐台识别时必填 |
| 分类 | 设备分类 | 是 | 设备主数据 |
| 分类 | 重要等级 | 是 | 关键、重要、一般 |
| 来源 | 供应商、订单、合同 | 是 | 关联采购入账 |
| 位置 | 工厂、车间、产线、工位 | 是 | 当前使用位置 |
| 责任 | 使用部门 | 是 | 设备责任组织 |
| 责任 | 设备负责人 | 是 | 设备业务负责人 |
| 责任 | 保管人 | 否 | 实际保管责任人 |
| 时间 | 发货时间 | 是 | 从采购入账带入 |
| 时间 | 入账时间 | 是 | 系统默认当前业务日期 |
| 时间 | 启用时间 | 按规则 | 入账完成后生成或补录 |
| 价值 | 原值/币种 | 按财务规则 | 可由财务回填 |
| 保障 | 质保起止 | 否 | 供应商质保信息 |
| 保障 | 服务商 | 否 | 维修服务商 |
| 监测 | IoT 编码 | 按设备规则 | 需要联网的设备填写 |
| 监测 | OEE 资格 | 按设备规则 | 是否纳入 OEE |
| 资料 | 验收单 | 按设备规则 | 作为入账附件，不形成独立验收流程 |
| 资料 | 设备档案 | 按设备规则 | 说明书、合格证、图纸等 |
| 资料 | 培训/交接资料 | 否 | 按设备类型配置 |

### 操作

- 开始办理
- 保存草稿
- 生成设备编码
- 逐台补录序列号
- 上传验收单
- 上传设备档案
- 预览台账
- 提交入账
- 退回采购补充信息

### 入账校验

1. 必须关联试用合格记录。
2. 设备名称、型号、品牌、分类、使用部门、位置和负责人必须完整。
3. 设备编码、资产编号、序列号不得重复。
4. 验收单和设备档案按设备类型配置为必传附件。
5. 数量大于 1 时，必须明确批量建档或逐台建档方式。
6. 需要联网的设备必须完成 IoT 编码校验，或明确待绑定状态。
7. 设备管理员提交后，正式生成设备台账和生命周期事件。

### 入账完成动作

1. 生成或更新设备台账。
2. 生成设备编码、二维码或资产卡片。
3. 写入入账时间和启用时间。
4. 将设备状态设置为“在用”或配置的初始状态。
5. 将合同、试用记录、验收单和设备档案关联到设备详情。
6. 写入生命周期履历。
7. 按现有规则触发监测、OEE、维修、备件、点检、保养和巡检的资格判断。

## 6.6 资产变更

### 保留范围

- 调拨
- 改造
- 借用
- 外送

### 不做范围

- 不做移位。
- 不单独建设普通位置编辑流程。
- 不将台账任意编辑视为变更完成。

### 申请字段

| 字段 | 说明 |
|---|---|
| 变更类型 | 调拨、改造、借用、外送 |
| 设备编码 | 支持选择在用设备 |
| 当前台账快照 | 变更前部门、位置、责任人和状态 |
| 变更原因 | 必填 |
| 目标部门/责任人 | 调拨时必填 |
| 借用方/外送方 | 对应类型必填 |
| 计划开始时间 | 必填 |
| 计划结束/预计归还时间 | 借用、外送必填 |
| 改造内容 | 改造时必填 |
| 改造后资料 | 改造时可上传 |
| 是否需要重新确认 | 改造时按规则判断 |
| 影响评估 | IoT、OEE、维修、备件、点检保养 |
| 附件和审批意见 | 支持多附件 |

### 业务规则

1. 变更必须形成单据，并保存变更前后快照。
2. 调拨完成后更新责任部门、位置和负责人。
3. 改造完成后补充改造资料，必要时重新提交使用部门确认。
4. 借用和外送必须记录预计归还时间、实际归还时间和接收确认。
5. 维修中、报废申请中、已归档设备原则上不得发起变更。
6. 外送期间设备状态为“外送”，不进入正常 OEE 统计。

## 6.7 闲置与再启用

### 保留范围

- 闲置申请
- 闲置复核
- 再启用申请

### 不做范围

- 不做保全计划。
- 不做定期通电、润滑、防锈和保全费用管理。
- 不新增保全任务。

### 闲置申请字段

- 设备编码
- 当前台账信息
- 闲置原因
- 闲置开始时间
- 预计闲置时长
- 当前保管地点
- 复核日期
- 盘活建议
- 附件和审批意见

### 复核结论

- 继续闲置
- 再启用
- 调拨
- 转报废

### 再启用字段

- 使用部门
- 设备负责人
- 使用位置
- 计划启用时间
- 使用确认意见
- 必要的设备资料和附件

再启用完成后恢复 `useStatus=在用`，同时重新判断监测、OEE、维修、点检、保养和巡检资格。

## 6.8 报废与归档

### 保留范围

- 报废申请
- 技术鉴定
- 审批
- 财务核销确认
- 设备状态变更
- 归档

### 不做范围

- 不做拆除、出售、回收、称重、运输和环保联单。
- 不在本系统维护处置去向和回收收入明细。

### 报废申请字段

- 设备编码、资产编号
- 报废原因
- 当前使用状态和运行年限
- 故障/淘汰说明
- 关联维修记录
- 原值、账面价值、残值（如有）
- 申请人和申请部门
- 技术鉴定附件
- 其他证明材料

### 流程

```text
报废申请
  → 技术鉴定
  → 部门/分管审批
  → 财务核销确认
  → 设备状态变更为已报废
  → 归档
```

### 业务规则

1. 技术鉴定未完成不得进入财务核销。
2. 财务核销未确认不得归档。
3. 报废申请中设备默认阻止新增普通维修。
4. 已报废设备不得出现在可用设备、正式 OEE、实时报警和待保养清单中。
5. 已归档设备只读保留，历史附件和履历可查询。

- 状态变化
- 附件上传和版本变化
- 关联流程任务及处理意见

### 履历字段

- 事件时间
- 事件类型
- 业务单据号
- 处理人
- 处理部门
- 处理动作
- 处理前状态
- 处理后状态

## 6.10 生命周期分析

### 一期指标

- 采购入账数量
- 试用合格率
- 试用不合格率
- 采购入账到设备入账平均周期
- 退回次数
- 待入账设备数量
- 闲置设备数量及占比
- 再启用数量
- 报废申请数量
- 已报废和已归档数量

### 统计规则

- 采购入账按任务创建时间统计。
- 试用合格率只统计已完成试用任务。
- 设备入账周期取首次采购入账提交到正式入账完成的时间。
- 闲置率分母为已入账设备，不含草稿和试用不合格设备。
- 已归档设备不纳入在用设备统计，但保留历史查询。

| 角色 | 权限 |
|---|---|
| 采购人员 | 新增/编辑采购入账、提交试用、处理试用不合格退回 |

`taskNo`、`sourceType`、`sourceSystem`、`sourceRef`、`equipmentName`、`model`、`brand`、`quantity`、`shipDate`、`contractNo`、`useDeptId`、`trialStatus`、`registrationStatus`、`deviceIds`、`currentNode`、`status`、`version`、`createdBy`、`createdAt`、`completedAt`。

### 8.4 状态字段

建议将状态拆分为：

- `assetStage`：待入账、已入账、已归档。
- `useStatus`：未启用、在用、闲置、再启用中、报废申请、已报废。
- `operationStatus`：运行、待机、计划停机、故障停机、维修中、无数据，沿用现有运行模块。
- `custodyStatus`：正常保管、借用、外送，沿用现有资产管理规则。

旧 `lifecycleStatus` 仅用于兼容展示，不作为新的可写事实源。

## 9. 与现有模块联动

### 9.1 设备台账

- 只有设备手续入账完成后，设备才生成正式台账。
- 台账的生命周期状态由业务单据驱动，不能通过普通编辑直接改成闲置或报废。
- 设备名称、型号、品牌等来源字段保留采购入账关联。

### 9.2 监测与报警

- 已入账且具备有效 IoT 绑定的在用设备进入正式监测。
- 试用不合格、闲置、报废申请和已归档设备不进入正式生产报警。
- 停止监测不等于删除历史采集和报警记录。

### 9.3 OEE

- 仅已入账、在用且满足既有 OEE 配置的设备纳入统计。
- 试用、闲置、外送和已报废设备不纳入正式 OEE。

### 9.4 维修与备件

- 已入账设备沿用现有维修和备件流程。
- 报废申请、调拨、闲置前检查是否存在未关闭维修工单。
- 存在关键阻断项时，系统阻止提交或要求授权人确认。

### 9.5 点检、保养、巡检

- 既有页面、菜单和路由必须保留。
- 生命周期模块只提供状态提示或联动事件，不替代点检、保养、巡检计划执行。
- 闲置和报废时按现有承接模块规则暂停或关闭计划。

### 9.6 综合文档库

合同、订单、发货凭证、试用记录、验收单、设备档案、变更资料、闲置资料和报废资料统一关联设备及业务单据。

## 10. 审计、幂等和异常处理

### 10.1 审计要求

以下动作必须生成生命周期事件：

- 新增、提交、撤回、退回
- 试用合格/不合格
- 设备手续入账
- 设备编码生成
- 调拨、改造、借用、外送
- 闲置、复核、再启用
- 报废申请、技术鉴定、财务核销、归档
- 关键附件上传、替换和删除

事件至少记录：

`eventId`、`taskNo`、`deviceId`、`action`、`before`、`after`、`operator`、`operatorDept`、`occurredAt`、`reason`、`attachmentRefs`、`sourceSystem`。

### 10.2 幂等和并发

- 外部同步以来源系统、外部单号、行号和版本作为幂等键。
- 手工新增使用本地单号唯一约束。
- 审批和提交动作携带版本号，防止重复点击和并发覆盖。
- 已完成任务重复提交时返回幂等结果，不重复生成台账或生命周期事件。

### 10.3 异常处理

| 异常 | 系统处理 |
|---|---|
| 外部单号重复 | 拒绝新增并提示已有任务 |
| WMS/SRM 数据不完整 | 进入待补充状态，不允许直接完成入账 |
| 手工记录无外部单号 | 标记人工来源，要求后续复核 |
| 试用不合格 | 退回采购，保留历史意见和附件 |
| 设备序列号重复 | 阻止入账，提示冲突设备 |
| 验收单/档案缺失 | 按设备类型规则阻止提交或要求例外原因 |
| 报废存在未关闭维修 | 阻止报废或要求授权处理 |
| 财务核销未确认 | 不允许归档 |
| 附件上传失败 | 保留业务单据，生成待补传提示 |

## 12. 验收标准

### 12.1 主流程

1. 采购人员可以手工新增或通过 SRM/WMS 带入采购入账。
2. 采购入账至少填写设备名称、型号、数量、品牌、发货时间、合同和使用部门。
3. 提交后只生成使用部门试用确认任务，不出现到货、安装、调试任务。
4. 使用部门提交合格后，系统生成设备手续入账待办。
5. 使用部门提交不合格时，必须填写主要问题和退回建议。
6. 设备管理员可以上传验收单和设备档案，并补全台账。
7. 入账完成后生成设备编码/资产卡片、设备台账和生命周期履历。

### 12.2 数据和权限

1. 采购核心字段提交后只读，退回后才可修改。
2. 使用部门只能处理本部门试用任务。
3. 设备管理员只能处理试用合格任务。
4. 外部来源字段保留来源系统和外部单号。
5. 历史试用意见、退回原因和附件不可被覆盖删除。

### 12.3 资产治理

1. 在用设备可以发起调拨、改造、借用和外送。
2. 页面不存在移位入口。
3. 闲置设备可以复核和再启用，页面不存在保全入口。
4. 报废设备经过技术鉴定和财务核销后才能归档。
5. 页面不存在处置执行、拆除、出售、回收和环保联单入口。
6. 已报废和已归档设备不出现在可用设备、正式 OEE 和实时报警清单中。

### 12.4 回归要求

新增生命周期模块不得删除或破坏：

- 设备台账和设备详情。
- 监测、报警、OEE。
- 维修、备件。
- 点检、保养、巡检及其 27 个既有页面。
- 报表中心和监测大屏。
