## 1. 文档说明

### 1.1 目标读者

- 产品经理、业务顾问、项目经理
- 设备管理、使用部门、仓储、质量、安全、财务人员
- 前端、后端、接口和测试人员
- SRM、WMS、ERP/财务、IoT、点巡保养承接系统负责人

### 1.2 阅读方式

本文档描述页面、单据、状态、字段、规则、接口和验收要求。  
其中“原型能力”指当前标准版前端演示可以模拟的内容；“生产能力”指正式上线必须由后端、工作流、附件、接口和审计共同提供的能力。

### 1.3 产品范围

本模块从“设备类物料的到货记录”开始，覆盖：

```text
收货记录
→ 到货核验
→ 设备实例识别
→ 安装
→ 调试/试运行
→ 技术验收
→ 设备建档
→ 正式启用
→ 变更/闲置/再启用
→ 报废/处置/归档
```

不在本模块实现：

- 采购申请、询价比价、采购订单创建、付款和供应商结算
- 仓库库存账、库位账和仓储作业
- ERP/财务的资本化、折旧、会计核销本体
- 真实 IoT 接入、协议解析和网关管理
- 点检、保养、巡检的完整计划和执行闭环

上述功能分别由 SRM、WMS、ERP/财务、IoT 平台和点巡保养承接模块负责，本系统通过接口或关联单据完成协同。

## 2. 业务边界与总体架构

### 2.1 系统职责

| 系统 | 权威数据和职责 | 本系统处理方式 |
|---|---|---|
| SRM | 物料主数据、物料分类、供应商、采购订单、订单行、采购收货、退货/冲销 | 保存外部引用和必要快照；不修改 SRM 事实 |
| WMS | 仓库实际收货、库位、入厂交接、暂存和仓储状态 | 接收设备类收货记录；不重复做仓库收货 |
| 设备管理系统 | 到货核验、设备实例、安装、调试、验收、资产建档、启用、变更、闲置、报废、生命周期履历 | 本文档设计范围 |
| ERP/财务 | 资产价值、资本化、折旧、资产核销、处置收入 | 通过接口或人工确认回执关联 |
| 宿主平台 | 身份、组织、角色、数据权限、统一待办、平台审计 | 本模块复用，不重复建设 |
| IoT/数据接入 | 设备联网、测点、数据采集、绑定和解绑 | 生命周期动作发起联动请求，失败进入补偿 |
| 点巡保养模块 | 点检、保养、巡检计划、任务和执行结果 | 生命周期事件触发暂停、恢复或专项任务 |

### 2.2 到货双来源原则

到货记录可以来自：

1. **SRM/WMS 同步**：以外部收货单号、收货行号和来源版本作为幂等依据。
2. **设备管理系统手工新增**：用于直送现场、临时收货、WMS 未覆盖或接口异常，必须标记 `MANUAL`，默认进入“待核验”。

两种来源必须使用同一张到货记录模型、同一状态机、同一详情页和同一后续流程。来源差异通过 `sourceType`、核验状态和对账状态体现，不得形成两套业务闭环。

### 2.3 业务对象关系

```text
物料主数据
  └─ 采购订单
      └─ 采购订单行
          └─ 到货记录
              └─ 到货明细
                  └─ 设备计划单元
                      └─ 设备实例
                          └─ 设备资产卡片
```

- 一个采购订单行可对应多次部分收货。
- 一条到货明细可对应多台设备实例。
- 成套设备通过父子关系关联主机、附机和组件。
- 验收、建档和启用必须落到设备计划单元或设备实例，不能只对整张收货单“一键通过”。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 典型职责 |
|---|---|
| 设备管理员 | 设备编码、到货核验、安装调试组织、验收组织、资产建档和状态维护 |
| 仓储/门卫 | 入厂、数量和外观核对、暂存、交接和收货凭证上传 |
| 使用部门 | 安装位置、使用条件、试运行、使用验收、责任人确认 |
| 厂家/服务商 | 安装、调试、培训、问题整改和保修服务 |
| 质量人员 | 质量检查、资料检查、验收意见和不合格处理 |
| 安全人员 | 安全条件、特种设备、施工许可和安全验收 |
| 采购/SRM 人员 | 采购订单、供应商、收货差异、退货和外部单号复核 |
| 财务/资产人员 | 原值、资本化、资产编号、核销和处置回执 |
| 部门负责人 | 本部门设备申请、变更、闲置和报废审批 |
| 分管领导 | 按设备类型、金额或组织范围进行最终审批 |
| 系统管理员 | 模板、编号规则、状态字典、接口和权限配置 |

### 3.2 权限粒度

权限至少包含以下四个维度：

- **功能权限**：查看、新增、编辑、提交、审批、执行、撤回、作废、导出。
- **数据权限**：本人、本部门、本工厂、授权组织、全局。
- **字段权限**：原值、残值、财务编号、报废意见等敏感字段可单独控制。
- **状态权限**：只有有权角色可以执行对应状态迁移。

### 3.3 RACI 最小矩阵

| 业务动作 | 发起 | 审核/确认 | 执行 | 关键约束 |
|---|---|---|---|---|
| 同步收货异常 | 集成服务/SRM/WMS | 采购、设备管理员 | 接口运维 | 不修改原始收货事实 |
| 手工新增到货 | 仓储/设备管理员 | 采购或设备管理员 | 设备管理员 | 必须标记人工来源并在建档前对账 |
| 到货确认 | 仓储/设备管理员 | 使用部门、质量 | 设备管理员 | 差异关闭人不能与检查人相同 |
| 安装调试 | 设备管理员 | 使用部门、安全/质量 | 厂家/工程人员 | 执行人与最终验收人分离 |
| 技术验收 | 设备管理员 | 使用、质量、安全、财务确认方 | 整改责任方 | 厂家不能代替甲方验收 |
| 调拨/闲置/复机 | 使用部门/设备管理员 | 原属部门、接收部门、设备负责人 | 设备管理员 | 原责任人和接收责任人双确认 |
| 报废/处置 | 使用部门/设备管理员 | 技术鉴定、财务、资产负责人、领导 | 处置执行人 | 鉴定、审批、处置确认分离 |

## 5. 生命周期工作台

### 5.1 页面用途

工作台面向设备管理员和管理人员，集中展示当前需要处理的业务，不替代各业务单据详情。

### 5.2 指标卡

- 待核验到货
- 待处理手工到货
- 待安装设备
- 调试中设备
- 待验收设备
- 验收超期设备
- 闲置复核到期
- 待审批报废
- 接口失败/对账异常

指标卡点击后带入对应筛选条件，不直接修改数据。

### 5.3 待办列表字段

| 字段 | 说明 |
|---|---|
| 待办类型 | 到货核验、安装、调试、验收、闲置复核、报废审批等 |
| 单据编号 | 业务单据号 |
| 设备/物料 | 设备名称、设备编码或物料编码 |
| 来源 | SRM、WMS、手工、系统动作 |
| 当前状态 | 当前业务状态 |
| 责任人 | 当前处理人或候选角色 |
| 截止时间 | 计划完成时间 |
| 逾期天数 | 超期时显示，未超期显示 `--` |
| 阻断项 | 未关闭维修、接口失败、资料缺失等 |
| 操作 | 查看、处理、转交、催办 |

### 5.4 异常区

异常至少包括：物料待分类、重复同步、序列号缺失、部分收货、收货冲销、到货不合格、调试失败、验收不通过、接口失败、人工对账超期和并发冲突。

每条异常必须展示：

- 异常编码和摘要
- 影响单据/设备
- 发生时间和来源
- 当前责任人
- 建议处理动作
- 重试、转人工、关闭或查看原始报文入口

## 6. 到货记录管理

### 6.1 页面用途

到货记录是设备生命周期的入口。页面处理“设备类物料已发生收货事实”后的设备业务，不重复记仓库收货。

### 6.2 到货记录列表

#### 查询条件

- 到货记录号
- 外部收货单号、外部收货行号
- 来源系统：SRM、WMS、手工
- 采购订单号/订单行号
- 物料编码、物料名称、设备类型
- 供应商
- 收货地点/仓库
- 到货时间范围
- 处理状态
- 核验状态
- 对账状态
- 是否存在异常

#### 列表字段

| 字段 | 说明 |
|---|---|
| 到货记录号 | 本系统唯一编号 |
| 来源 | `SRM`、`WMS`、`MANUAL` |
| 外部收货单号 | 同步记录显示；手工未关联时显示 `--` |
| 采购订单/行 | 只读引用 |
| 物料编码/名称 | 来自物料快照 |
| 设备类标识 | 设备、非设备、待分类 |
| 收货数量 | 原始数量和已识别数量 |
| 供应商 | 外部引用 |
| 收货地点 | 仓库、厂区或现场 |
| 到货时间 | 来源时间；与同步接收时间分开 |
| 处理状态 | 待核验、已确认、隔离、已关闭等 |
| 对账状态 | 未对账、待复核、已对账、差异 |
| 异常标记 | 重复、退货、冲销、资料缺失等 |
| 最后更新时间 | 本系统更新时间 |

#### 页面操作

- `新建手工到货`
- `导入/同步重试`
- `批量核验`
- `查看详情`
- `导出`
- `发起对账`
- `关闭记录`（仅满足关闭条件）

系统同步记录禁止编辑原始收货数量、时间和来源单号；更正通过来源系统新版本或反向事件处理。

### 6.3 手工新增到货

#### 适用场景

- 设备直送现场，没有经过 WMS
- WMS/SRM 暂未覆盖的收货场景
- 外部接口暂时不可用，需要先登记现场事实
- 历史设备补录

#### 表单字段

| 分组 | 字段 | 必填 | 说明 |
|---|---|---:|---|
| 来源 | 来源类型 | 是 | 固定为手工 |
| 来源 | 来源说明 | 是 | 直送、临时、接口异常、历史补录等 |
| 来源 | 采购订单号/行号 | 原则必填 | 无法关联时需填写例外原因 |
| 来源 | 外部收货单号 | 否 | 后续可补录 |
| 物料 | 物料编码 | 原则必填 | 可从 SRM 物料快照选择 |
| 物料 | 物料名称、型号、品牌 | 是 | 无物料编码时人工填写并待复核 |
| 物料 | 物料分类/设备类标识 | 是 | 不允许按名称自动猜测 |
| 供应商 | 供应商 | 原则必填 | 无供应商需说明原因 |
| 收货 | 收货数量、单位 | 是 | 支持部分收货 |
| 收货 | 收货时间 | 是 | 不得晚于当前时间 |
| 收货 | 收货地点 | 是 | 仓库、厂区、产线、现场 |
| 识别 | 批次、箱号、序列号 | 按物料规则 | 序列号缺失需设置补录期限 |
| 凭证 | 收货凭证 | 是 | 送货单、现场照片、签收单等 |
| 责任 | 收货人、责任人 | 是 | 用于后续核验 |
| 例外 | 例外原因、补录期限 | 条件必填 | 无外部单号时必须填写 |
| 备注 | 备注 | 否 | 现场说明 |

提交后：

1. 生成本系统到货记录号。
2. `sourceType=MANUAL`。
3. 状态为“待核验”。
4. 生成对账待办。
5. 不得直接进入“已建档”或“在用”。

### 6.4 到货记录详情

详情页采用 Tab：

1. 基本信息
2. 收货明细
3. 来源与对账
4. 开箱核验
5. 设备实例
6. 异常与整改
7. 附件
8. 操作履历

#### 基本信息

展示系统编号、来源、外部单号、采购订单、物料、供应商、收货地点、收货时间、数量、状态和责任人。

#### 开箱核验项目

- 包装和外观
- 铭牌、型号、制造号
- 数量和单位
- 随机附件、备件和工具
- 说明书、合格证、校准证书
- 环保/安全证书
- 现场照片
- 差异说明

每项结果为：未检查、合格、不合格、不适用，并支持备注和附件。

#### 操作前置条件

- 物料必须已识别为设备类，或由授权人员完成分类复核。
- 收货数量必须大于零。
- 手工记录必须有凭证和责任人。
- 不合格记录必须填写隔离位置和责任方。
- 到货确认前必须完成必填开箱项目。

#### 状态变化

```text
待核验 → 已确认
待核验 → 待分类
待核验 → 不合格隔离
已确认 → 待安装
不合格隔离 → 整改中 → 待复核
待核验/已确认 → 退货影响/冲销影响
```

### 6.5 退货、冲销和数量更正

- 原始收货记录不可物理删除。
- SRM/WMS 回传退货、冲销或更正版本时，生成反向事件。
- 若设备尚未安装，可直接调整待处理数量。
- 若设备已安装、调试或验收，必须生成异常单，由设备管理员、采购/仓储共同确认影响。
- 已形成设备实例的记录不得通过修改数量删除实例；应使用拆分、退回或作废业务单保留历史。

## 7. 设备实例识别与资产建档

### 7.1 设备计划单元

设备计划单元用于把收货数量拆分为可跟踪对象：

- 单台设备：数量 1，对应一个实例。
- 多台同型号设备：按数量批量生成计划单元，再补充序列号。
- 成套设备：生成主机、附机和组件关系。
- 序列号缺失：允许先生成待识别计划单元，但必须在验收前补齐或确认“不适用”。

### 7.2 实例识别页面

#### 字段

- 设备计划单元号
- 设备名称、型号、品牌
- 序列号、制造号、铭牌号
- 设备类型和重要等级
- 父设备/子设备
- 收货批次、箱号
- 设备照片
- 识别人、识别时间

#### 操作

- 新增设备实例
- 批量生成实例
- 绑定序列号
- 建立父子关系
- 拆分成套设备
- 标记序列号不适用
- 提交复核

#### 校验

- 序列号在同一设备类型下不得重复。
- 已绑定其他资产的序列号不能再次绑定。
- 父设备不能绑定为自己的子设备。
- 成套设备的组件数量必须与收货明细可解释。

### 7.3 资产建档

资产建档可由验收通过触发，也可以在验收前创建“草稿档案”，但草稿不能进入正式在用状态。

#### 建档字段

| 分组 | 字段 |
|---|---|
| 标识 | 设备编码、资产编号、二维码、序列号、制造号 |
| 基础 | 设备名称、设备类型、品牌、型号、规格、重要等级 |
| 来源 | 供应商、采购订单、合同、到货记录、资产来源 |
| 位置 | 工厂、车间、产线、工位、安装位置 |
| 责任 | 使用部门、设备负责人、保管人 |
| 时间 | 到货日期、安装日期、调试日期、验收日期、启用日期 |
| 价值 | 原值、币种、残值、资本化日期、财务资产编号 |
| 保障 | 质保起止、服务商、保养周期、关键备件 |
| 连接 | IoT 绑定、监测编码、OEE 资格 |
| 文档 | 说明书、图纸、验收单、培训记录、证书 |

### 7.4 建档和启用分离

- 建档：形成可识别的资产档案。
- 启用：表示满足正式使用条件并可进入正式运行管理。
- 资本化：由财务系统确认，不由设备验收自动推导。

启用前置条件：

1. 验收结论为“通过”，或符合配置的“条件通过”放行规则。
2. 位置、责任人和使用部门已确认。
3. 必备资料齐套。
4. 必要的联网、安全、计量和证照条件满足。
5. 未存在未关闭的阻断项。

## 8. 安装管理

### 8.1 页面用途

记录设备从暂存/到货状态转入安装现场的计划、条件、过程和交接。

### 8.2 安装任务列表

查询条件：任务号、设备、车间、厂家、负责人、计划日期、状态、是否逾期。

列表字段：任务号、设备编码、安装位置、厂家、负责人、计划开始/结束、实际开始/结束、状态、逾期天数、异常。

### 8.3 安装任务详情

#### 计划信息

- 设备实例
- 安装位置
- 计划开始/结束
- 施工负责人
- 厂家/服务商
- 关联合同或服务单

#### 安装条件清单

- 基础和地脚
- 供电
- 气源/水路/排风
- 网络
- 吊装和搬运
- 安全防护
- 环境温湿度
- 计量和校准

每项支持结果、说明、照片和责任人。

#### 安装操作

- 开始安装
- 暂停
- 提交完成
- 退回整改
- 生成调试任务

安装完成前不得进入调试中；高风险施工未完成安全确认时不得开始安装。

## 9. 调试与试运行

### 9.1 调试任务

调试任务由安装完成生成，也可由授权人员手工创建。

字段：

- 调试任务号
- 设备实例
- 调试方案模板
- 调试负责人和厂家
- 计划日期
- 调试环境
- 目标参数
- 试运行时长
- 关联安装任务

### 9.2 调试项目

按设备类型配置模板，至少支持：

- 空载运行
- 负载运行
- 精度/重复性
- 节拍/产能
- 报警
- 安全联锁
- 急停
- 网络和数据
- 能耗
- 试运行产量和良率
- 培训和交接

每个项目记录目标值、实测值、单位、结果、偏差、附件和处理意见。

### 9.3 调试问题闭环

字段：问题编号、问题描述、严重等级、责任方、计划完成日、整改措施、整改附件、复验人、复验结论。

状态：

```text
待处理 → 整改中 → 待复验 → 已关闭
                    └→ 复验不通过 → 整改中
```

调试失败不能直接发起正式验收，除非由授权人员填写例外原因并走配置的放行审批。

### 9.4 试运行

试运行设备的 `useStatus=试运行`：

- 可以采集监测数据和调试报警。
- 默认不计入正式 OEE。
- 可以登记试运行问题，不生成普通生产维修统计。
- 点巡保养可使用专项试运行计划。
- 试运行结束必须转正式启用、继续试运行或退回整改。

## 10. 验收管理

### 10.1 验收申请

验收申请自动带出：

- 采购订单和收货记录
- 设备实例和资产草稿
- 安装记录
- 调试记录和试运行数据
- 物料技术规格
- 质保条款
- 已关闭/未关闭问题

提交前校验：

- 安装已完成。
- 必填调试项目完成。
- 严重问题已关闭。
- 序列号和设备实例已确认。
- 必备资料已上传或有例外审批。

### 10.2 验收清单

| 类别 | 示例项目 |
|---|---|
| 技术 | 型号、规格、参数、功能 |
| 性能 | 产能、精度、节拍、稳定性 |
| 质量 | 外观、制造质量、缺陷 |
| 安全 | 防护、联锁、急停、证照 |
| 环保 | 噪声、排放、危险物料 |
| 资料 | 说明书、图纸、合格证、校准证 |
| 备件 | 随机备件、工具、易损件 |
| 培训 | 操作、维修、安全培训和签到 |
| 资产 | 铭牌、编码、位置、责任人 |

### 10.3 验收结论

- **通过**：满足全部必选项目。
- **条件通过**：存在可控尾项，允许范围由模板配置。
- **整改后复验**：不满足放行条件，整改后重新验收。
- **不通过**：重大质量、安全或性能问题。
- **退货**：由采购/SRM 继续处理，本系统保留影响记录。

“条件通过”必须拆分配置：

| 门槛 | 是否允许由条件通过放行 |
|---|---|
| 受限试运行 | 可配置，默认允许 |
| 正式生产 | 默认不允许 |
| 正式启用 | 默认不允许 |
| 资本化 | 以财务规则为准，默认不自动触发 |
| 质保起算 | 以合同/验收规则为准 |

### 10.4 验收签署

签署人至少包括设备管理员、使用部门、质量/安全（按设备类型）和厂家代表；涉及资产价值的设备增加财务确认。生产版应保存签署时间、身份、意见、附件版本和签名/电子签证据。

## 11. 正式启用

### 11.1 启用动作

启用是聚合命令，至少一次性完成：

1. 更新设备资产状态。
2. 写入启用日期和质保起始规则。
3. 确认位置、责任人和使用部门。
4. 生成或激活二维码。
5. 按配置绑定 IoT/监测编码。
6. 更新 OEE 准入资格。
7. 触发点巡保养承接模块创建计划或生成待办。
8. 写入生命周期事件和审计记录。

任一外部副作用失败时，设备状态不得静默显示为全部成功，应显示“启用处理中/待补偿”并进入补偿队列。

### 11.2 启用后联动

- `useStatus=在用`。
- 允许正式监测、报警、维修、备件和 OEE。
- 允许创建正式点检、保养和巡检计划。
- 在设备详情展示启用日期、质保期和履历。

## 12. 资产变更管理

### 12.1 变更类型

- 调拨：部门、车间、产线、工位和责任人变化。
- 移位：安装位置变化。
- 责任人变更。
- 技术改造：参数、结构、功能或产能变化。
- 借用/外送/返厂/归还。
- 拆分/合并：父子资产关系变化。
- 属性纠正：名称、分类、型号、重要等级等。

### 12.2 变更申请字段

- 变更单号和类型
- 设备/资产
- 变更前快照
- 变更后内容
- 原因和业务说明
- 计划生效时间
- 影响范围：监测、报警、OEE、维修、点巡保养、备件
- 是否需要重新调试/验收
- 附件
- 发起人、审批人、执行人

### 12.3 变更规则

- 维修中、报废审批中、处置中的设备默认禁止调拨和删除。
- 变更前必须检查未关闭工单、借用/外送、接口任务和资产绑定。
- 改造涉及关键参数或安全条件时，必须重新调试/验收。
- 变更生效使用业务单据，不能直接覆盖台账历史。
- 错误变更使用反向变更单纠正。

### 12.4 变更联动

| 变更 | 监测/IoT | OEE | 维修 | 点巡保养 |
|---|---|---|---|---|
| 位置变更 | 更新绑定位置 | 更新产线归属 | 保留工单并记录位置快照 | 更新计划对象 |
| 责任人变更 | 更新告警接收人 | 无直接影响 | 更新责任人 | 更新执行人 |
| 技术改造 | 重新确认测点 | 重新校验速度 | 可生成专项工单 | 生成专项点检 |
| 拆分/合并 | 重新建立设备关系 | 重新评估资格 | 迁移或关闭关联工单 | 迁移计划 |
| 外送/返厂 | 受控停用或保留 | 暂停统计 | 保留返厂工单 | 转专项保全 |

## 13. 闲置、停用与再启用

### 13.1 闲置申请

字段：

- 设备和当前资产状态
- 闲置原因
- 预计开始/结束时间
- 闲置位置
- 保管责任人
- 保全措施
- 是否拆除、封存或断能
- 是否保留 IoT 监测
- 闲置期间预计费用
- 复核周期

### 13.2 闲置审批前置校验

- 不存在未关闭维修，或已完成转移/关闭说明。
- 借用、外送和返厂事项已处理。
- 关联备件、库存和拆下件有处理方案。
- 点巡保养计划已暂停或切换为保全计划。
- 监测和报警策略已确认。

### 13.3 闲置期间

- `useStatus=闲置`。
- 不参与正式 OEE。
- 暂停生产报警，保留必要的环境/保全监测。
- 自动生成周期复核待办。
- 记录现场复核、保全检查、异常和照片。

### 13.4 再启用

再启用申请必须完成：

1. 设备外观和安全检查。
2. 关键部位保养和润滑。
3. 计量/校准确认。
4. 联网和参数校验。
5. 空载/负载试运行。
6. 责任人、位置和使用部门确认。

再启用可直接进入“在用”，也可先进入“试运行”；若改造或长期闲置超过阈值，必须重新走验收。

## 14. 报废与处置

### 14.1 报废申请

字段：

- 报废单号和设备
- 报废原因：技术淘汰、故障无法修复、质量问题、安全风险、闲置无利用价值等
- 使用年限和累计运行
- 维修成本和预计维修成本
- 技术鉴定意见
- 原值、账面价值、预计残值
- 是否含危险物料/特种设备
- 拆除方案
- 处置方案
- 环保和安全要求
- 附件和照片

### 14.2 技术鉴定

技术鉴定人填写：

- 故障/缺陷事实
- 可修复性和维修经济性
- 继续使用风险
- 可拆件/可复用件
- 建议结论

鉴定结论：同意报废、维修后继续使用、转闲置、内部调剂、补充资料。

### 14.3 审批

审批级别按设备类型、原值、账面价值或组织配置：

```text
申请 → 技术鉴定 → 设备负责人 → 财务/资产 → 部门负责人
     → 安全/环保（条件触发） → 分管领导 → 待处置
```

### 14.4 处置记录

字段：

- 拆除日期、拆除负责人
- 交接人和交接时间
- 处置方式：报废、出售、回收、捐赠、内部调剂、返厂
- 处置对象和去向
- 残值、回收收入、费用
- 环保/安全凭证
- 财务核销单号和回执
- 拆除前后照片

### 14.5 归档规则

只有以下条件全部满足，才允许“已处置 → 已归档”：

- 处置证据齐套。
- 财务核销回执已确认或已完成明确人工放行。
- 未关闭维修、借用、外送、库存和联网解绑事项已处理。
- 资产历史和附件已固化。
- 设备进入只读历史，不出现在可用设备、实时报警和正式 OEE 清单。

## 15. 设备详情生命周期履历

在现有设备详情中新增以下 Tab：

1. **生命周期概览**：四状态轴、当前责任人、位置、关键日期和阻断项。
2. **采购与到货**：物料、订单、收货、来源、对账和退货影响。
3. **安装调试**：安装任务、调试项目、试运行和问题。
4. **验收与建档**：验收清单、结论、签署、资产编号和质保。
5. **变更记录**：前后快照、审批、执行和影响。
6. **闲置/报废**：申请、复核、鉴定、处置和归档。
7. **文档与证据**：附件版本、来源、哈希、签署人和关联单据。
8. **事件时间线**：按事件时间和业务时间展示全部状态变化。

时间线事件字段：事件类型、业务单号、发生时间、业务时间、操作人、来源系统、前值、后值、原因、附件和关联对象。

## 16. 状态字典与状态迁移

### 16.1 四个状态轴

| 状态轴 | 枚举 |
|---|---|
| `assetStage` | 待核验、待收货确认、待安装、调试中、待验收、已建档、已处置、已归档 |
| `useStatus` | 未启用、试运行、在用、闲置、停用、报废申请、已报废 |
| `operationStatus` | 运行、待机、计划停机、故障停机、维修中、无数据 |
| `custodyStatus` | 在途、在厂待检、暂存、正常保管、借用、外送、处置中 |

现有 `lifecycleStatus` 仅作为过渡展示字段，不再作为可写事实源。

### 16.2 关键迁移

```text
待核验 → 待收货确认 → 待安装 → 调试中 → 待验收
待验收 → 整改中 → 待验收
待验收 → 已建档 → 试运行 → 在用
在用 → 闲置 → 试运行/在用
在用/闲置/停用 → 报废申请 → 已处置 → 已归档
```

### 16.3 状态迁移控制

每次迁移必须校验：

- 当前状态是否允许该动作。
- 角色是否有权限。
- 必填字段、附件和审批是否齐套。
- 是否存在设备级阻断项。
- `lifecycleVersion` 是否匹配。
- 外部副作用是否已完成或进入可补偿状态。

## 17. 核心业务规则

### 17.1 来源和幂等

- 同步记录唯一键：`sourceSystem + sourceReceiptId + sourceReceiptLineId + sourceVersion`。
- 手工记录唯一键：本系统 `manualReceiptId`。
- 同一实际收货同时来自多个来源时，必须进入对账，不得静默合并。
- 重复消息只返回原单据，不重复生成实例或资产。

### 17.2 数量和序列号

- 支持分批收货和部分收货。
- 已识别数量不得超过收货数量，除非有更正版本。
- 序列号管理设备必须在验收前补齐序列号或确认不适用。
- 退货、冲销不得删除已生成实例，必须产生反向事件。

### 17.3 审批和撤回

- 草稿可编辑。
- 已提交未审批可撤回。
- 审批中不可直接修改关键事实，需撤回或发起变更。
- 驳回必须填写原因，可按配置退回指定节点。
- 已完成单据只能通过反向业务单纠正。

### 17.4 并发与重复提交

- 所有命令携带 `commandId`、`idempotencyKey` 和 `expectedVersion`。
- 重复点击返回首次处理结果。
- 版本冲突时阻止提交并提示刷新，不覆盖其他人的变更。

### 17.5 附件和证据

- 关键验收、报废、处置附件必须版本化。
- 附件保存原文件名、类型、大小、哈希、上传人、上传时间和业务关联。
- 关键证据不可物理删除，只能作废并保留作废原因。

### 18.2 `equipment_instances` 设备实例

关键字段：实例号、设备计划单元、序列号、制造号、铭牌号、父设备、设备类型、收货明细、识别人、识别时间、状态。

### 18.3 `device_assets` 资产卡片

关键字段：设备编码、资产编号、设备实例、名称、类型、型号、品牌、位置、责任人、原值、资本化日期、启用日期、质保、IoT 编码、OEE 资格、四状态轴、版本号。

### 18.4 业务单据公共字段

所有安装、调试、验收、变更、闲置、报废、处置单据统一具备：

- `id`、`billNo`、`billType`
- `subjectType`、`subjectId`
- `status`
- `applicantId`、`ownerId`
- `workflowInstanceId`
- `expectedVersion`
- `commandId`
- `createdAt`、`updatedAt`
- `submittedAt`、`completedAt`
- `attachments`
- `auditRefs`

### 18.5 设备级阻断项 `device_blockers`

字段：设备、阻断类型、来源单据、阻断描述、严重级别、责任人、创建时间、解决时间、解决凭证。

阻断类型至少包括：维修未关闭、借用未归还、外送未回厂、序列号缺失、验收未完成、接口失败、财务未核销、库存/备件未处理、联网变更未完成。

## 19. SRM/WMS 接口设计

### 19.1 物料同步

方向：SRM → 设备管理系统。  
用途：设备物料分类和设备类型规则。

最小字段：物料编码、名称、型号、品牌、分类、设备类标识、序列号规则、成套规则、安装调试标识、验收模板、质保规则、版本和生效时间。

分类缺失时进入“待分类”队列，不得按物料名称猜测为设备。

### 19.2 采购订单引用同步

方向：SRM → 设备管理系统。  
用途：到货记录关联采购订单行和数量核对。

最小字段：采购订单号、订单行号、物料、供应商、订购数量、单位、订单日期、合同引用、订单状态、外部版本。

本系统不允许新建或修改 SRM 采购订单。

### 19.3 收货记录同步

方向：WMS/SRM → 设备管理系统。  
最小字段：

```text
sourceSystem
sourceReceiptId
sourceReceiptLineId
sourceVersion
purchaseOrderId
purchaseOrderLineId
materialCode
materialCategory
assetizationFlag
materialName
model
brand
supplierId
receivedQty
unit
receiptTime
warehouse/site
batchNo
serialNo
attachments
```

处理要求：

- 服务端唯一约束控制重复。
- 同步失败可重试。
- 业务校验失败进入异常队列，不丢弃原始报文。
- 退货、冲销和数量更正通过反向事件或新版本同步。
- 设备管理系统保存原始报文摘要和处理结果。

### 19.4 对账接口

支持按收货单、订单行、物料、数量、序列号和时间进行对账。差异类型：

- 本系统有、来源系统无
- 来源系统有、本系统未接收
- 数量差异
- 序列号差异
- 供应商/物料差异
- 退货/冲销未同步

## 20. 手工新增与对账机制

### 20.1 手工记录生命周期

```text
草稿 → 待核验 → 待外部对账 → 已确认
                    └→ 差异处理 → 已确认/关闭
```

若无外部单号，必须：

- 填写例外原因。
- 指定责任人。
- 指定补录期限。
- 在建档或验收前完成采购/仓储复核，或由授权人员人工放行。

### 20.2 对账页面

字段：本系统到货记录、外部单号、来源、订单行、物料、数量、序列号、差异类型、责任人、期限、处理意见、凭证、状态。

操作：匹配、拆分匹配、合并说明、补录外部单号、调整差异、发起复核、关闭差异、重新同步。

## 21. 与现有模块联动

### 21.1 设备台账

- 台账是资产主数据展示入口。
- 新增和状态变更必须来自生命周期单据。
- 普通编辑不得直接修改启用、闲置、报废等事实状态。

### 21.2 监测、报警和 IoT

- 只有 `useStatus=在用` 且联网绑定有效的设备进入正式监测和报警。
- 试运行设备可按策略进入调试监测。
- 闲置、停用、报废申请设备暂停生产报警，保留必要历史和保全监测。
- 解绑、停用采集和删除历史绑定必须分开处理。

### 21.3 OEE

- 未启用、试运行、闲置、停用、报废设备默认不参与正式 OEE。
- 设备位置、产线和技术改造变更时重新校验 OEE 资格。
- OEE 页面通过统一生命周期选择器读取准入，不得复制状态条件。

### 21.4 维修和备件

- 闲置、调拨和报废前检查维修工单。
- 报废前处理拆下件、可复用件和库存关联。
- 报废申请中禁止新建普通维修，特殊维修需走例外审批。

### 21.5 点检、保养、巡检

- 既有 27 个点检/保养/巡检页面必须保留。
- 生产版由承接模块创建、暂停、恢复和关闭计划。
- 当前标准版仅展示联动提示或模拟事件，不宣称执行任务真实落库。

### 21.6 文档中心

采购、到货、安装、调试、验收、质保、变更、报废和处置附件统一关联设备和业务单据，并支持版本和权限控制。

## 22. 异常、补偿与审计

### 22.1 异常分类

- 数据异常：物料待分类、缺少订单、序列号重复。
- 业务异常：到货不合格、调试失败、验收不通过。
- 集成异常：超时、格式错误、重复消息、外部撤销。
- 并发异常：版本冲突、重复提交。
- 依赖异常：IoT、财务、点巡保养承接失败。

### 22.2 补偿队列

每个跨系统副作用保存：

- 命令号、幂等键
- 目标系统和接口
- 请求摘要和响应摘要
- 当前状态：待执行、执行中、成功、失败、人工处理
- 重试次数、下次重试时间
- 最后错误码和责任人

支持自动重试、人工重试、转人工确认和关闭。关闭必须填写原因和证据。

### 22.3 审计事件

`lifecycle_events` 追加写入：

- 设备和业务单据
- 动作和状态前后值
- 操作人、组织、角色
- 来源系统和命令号
- 时间、原因和意见
- 附件引用
- 工作流节点

## 23. 报表与指标

### 23.1 管理指标

- 设备类收货量、设备识别率
- 收货到启用周期
- 安装周期、调试周期、验收周期
- 验收一次通过率
- 条件通过率和整改关闭周期
- 手工到货占比、手工对账及时率
- 接口成功率和补偿时长
- 在用、闲置、停用设备数量和原值
- 闲置复核及时率、再启用率
- 报废申请到归档周期
- 处置回收率和未归档设备数

### 23.2 指标口径

迭代 0 固化字段级公式：

- 周期起点、终点使用业务时间，不使用页面打开时间。
- 验收一次通过率分母为进入首次验收的设备计划单元。
- 闲置率明确按数量、原值或设备台数计算。
- 处置回收率明确是否包含残值、出售收入和处置费用。
- 接口成功率区分首次成功和补偿后成功。

## 24. 原型一期设计范围

一期仅跑通一台设备的主路径：

```text
SRM/WMS 收货同步
或
手工新增到货
→ 来源核验
→ 到货确认
→ 安装
→ 调试
→ 验收
→ 建档
→ 启用
```

### 24.1 一期页面

- 生命周期工作台
- 到货记录列表/详情
- 到货核验和手工新增
- 安装调试
- 设备验收
- 资产建档/启用
- 设备详情生命周期履历

### 24.2 一期原型口径

- 使用 DemoStore、模拟工作流和演示数据。
- 模拟 SRM/WMS 外部单号、同步状态和接口异常。
- 模拟附件、审批意见和生命周期事件。
- 不实现真实鉴权、真实附件存储、真实接口和真实电子签。
- 不删除或替换既有点检、保养、巡检页面。

## 25. 生产版非功能要求

### 25.1 一致性

- 状态变更、事件、审批和副作用具备事务边界。
- 使用乐观锁防止并发覆盖。
- 使用 outbox/补偿机制保证外部动作可重放。

### 25.2 安全和权限

- 复用宿主平台身份和数据权限。
- 敏感财务字段按角色脱敏。
- 附件下载和导出记录审计。
- 关键审批支持电子签或平台签署证据。

### 25.3 可用性

- 外部接口失败不阻塞无关本地操作。
- 业务单据支持草稿、撤回、重试和恢复。
- 页面展示“业务状态”和“接口状态”两个维度。

### 25.4 性能

- 到货列表、工作台和设备履历支持分页。
- 批量收货和批量实例生成采用异步任务。
- 报表查询使用汇总或异步导出，不能阻塞交易接口。

### 25.5 数据保留

- 生命周期事件、审批记录、关键附件和原始接口报文按企业审计周期留存。
- 已归档设备只读，但历史事件和报表可查询。

## 26. 验收用例

### 26.1 收货入口

1. 接收一条 SRM 收货记录，生成设备类到货记录。
2. 接收一条 WMS 收货记录，进入同一列表和详情流程。
3. 手工新增直送现场到货，默认待核验并生成对账待办。
4. 手工新增无外部单号，强制填写例外原因、责任人和期限。
5. 重复推送同一外部收货行，不生成重复记录。
6. 物料未分类时进入待分类，不允许直接启用。
7. 支持部分收货和一条收货对应多台设备。
8. 收货冲销、退货、数量更正保留原记录并生成反向事件。

### 26.2 到货、安装、调试、验收

1. 到货核验完成后才能进入安装。
2. 安装条件未满足时不能开始安装。
3. 调试项目、问题整改和复验记录完整保留。
4. 调试失败不能直接正式验收。
5. 验收不通过不能启用。
6. 条件通过只能按配置进入受限试运行。
7. 验收复验保留原意见、附件和历史版本。

### 26.3 建档和启用

1. 一条收货明细可生成多个设备实例。
2. 序列号重复或缺失时给出明确阻断。
3. 建档后未验收通过的设备不能显示为在用。
4. 启用动作同步更新台账、生命周期履历和工作台。
5. IoT、OEE 或点巡保养联动失败时进入补偿队列，不静默成功。

### 26.4 变更、闲置和报废

1. 在用设备可调拨并保存前后快照。
2. 维修中设备申请闲置时被阻断或要求明确例外审批。
3. 闲置设备按周期生成复核待办。
4. 再启用前必须完成检查和试运行。
5. 报废申请经过鉴定和审批后才能处置。
6. 未完成财务核销、拆除或关联事项时不能归档。
7. 已归档设备不进入实时、报警和正式 OEE，但历史可查。

### 26.5 生产化测试

- 非法状态迁移、撤回、驳回、复验和重新打开。
- 重复点击、重复消息、跨标签提交和版本冲突。
- 接口延迟、失败、死信、补偿、人工关闭。
- 存量快照迁移、旧状态映射和回滚。
- 权限越权、组织数据隔离、敏感字段和附件审计。

### 27.1 迭代 0：规则和接口基线

- 冻结状态轴、迁移矩阵和联动矩阵。

- 确认 SRM/WMS/财务/IoT/点巡保养接口契约。

- 工作台
- 同步/手工到货
- 到货核验
- 实例识别
- 安装调试
- 验收
- 建档和启用

### 27.3 迭代 2：资产治理

- 调拨、移位、责任人变更

## 29. 设计结论

本设计采用“SRM/WMS 产生或提供收货事实，设备管理系统从设备类到货记录开始管理设备生命周期”的边界。同步到货和手工新增共用一个数据模型和状态机，手工记录是受控兜底而不是第二套流程。

一期先实现收货到启用的最小闭环，重点验证设备实例、验收门槛、资产建档、正式启用和跨模块状态联动；资产变更、闲置/再启用、报废/处置分别在后续迭代建设。生产上线前必须完成接口契约、工作流、附件、审计、幂等、并发、补偿和存量迁移设计。
