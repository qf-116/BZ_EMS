# 基础配置模块 需求细则

> 版本：v1.0（2026-09-22）｜ 需求背景：设备管理系统标准版从原数字化宿主平台拆分为独立系统运行，原由宿主平台统一提供的账号 / 角色 / 组织 / 字典 / 日志等基础能力改由本系统自建，形成「基础配置」模块。
> 功能口径参考特变项目系统管理模块（用户 / 角色 / 组织机构 / 字典 / 日志管理），并按本项目后台 UI 规范（docs/后台UI设计与交互规范.md）落地。
> 前端演示范围：页面数据为只读演示种子（src/data/systemConfig.js），增删改等交互页面内生效（刷新恢复），不写入 DemoStore。

---

## 0. 模块总览

| 菜单 | 路由 | 页面 | 说明 |
|------|------|------|------|
| 基础配置 | `/system/users` | 用户管理 | 登录账号全生命周期 |
| 基础配置 | `/system/roles` | 角色管理 | RBAC 角色 + 功能/数据权限 |
| 基础配置 | `/system/org` | 组织机构 | 部门树 + 部门人员 |
| 基础配置 | `/system/dict` | 字典管理 | 字典类型 + 字典项两级枚举 |
| 基础配置 | `/system/logs` | 日志管理 | 登录日志 + 系统操作日志（Tabs） |

- 旧入口迁移：`/permissions` → 角色管理（权限 = 角色功能权限 + 用户绑定），`/audit` → 日志管理（操作日志）。
- 权限模型：**RBAC** —— 用户绑定角色（可多选），角色携带「功能权限树勾选」+「数据权限范围」；数据权限按组织机构树过滤。

## 1. 用户管理（/system/users）

### 1.1 页面目标
维护系统登录账号：新增、编辑、启用 / 停用、重置密码、删除、批量启停用、导入导出；登录控制以本页账号状态为准。

### 1.2 列表字段
| 字段 | 说明 |
|------|------|
| 工号 | U + 4 位序号，系统自动生成，不可编辑 |
| 姓名 / 登录账号 | 账号全局唯一，创建后不可修改 |
| 所属部门 | 组织机构路径（如 设备部 / 维修科） |
| 角色 | Tag 展示，可多选，至少 1 个 |
| 手机号 / 邮箱 | 手机号必填（登录异常通知）；邮箱选填、格式校验 |
| 状态 | 正常 / 停用 |
| 最近登录 | 空值显示 `--`（未登录过） |

### 1.3 操作规则
1. **新增用户**：初始密码统一 `Dh@2026`，首次登录强制修改密码；账号规则：字母开头，3-20 位字母/数字/下划线。
2. **编辑用户**：账号、工号不可改；部门 / 角色 / 状态修改即时生效。
3. **重置密码**：二次确认，旧密码立即失效并重置为初始密码；动作写入操作日志。
4. **停用**：二次确认，停用后立即无法登录，历史日志保留；启用同样二次确认。
5. **删除**：二次确认；内置系统管理员（U0001）不允许删除 / 停用；历史日志按账号归档保留。
6. **批量启用 / 停用**：需先勾选（未勾选时禁用并提示「请先勾选数据」）。
7. **登录锁定**：密码连续输错 5 次锁定 30 分钟，失败原因记入登录日志。

### 1.4 筛选
关键词（工号 / 姓名 / 账号 / 手机号）+ 部门（含子部门）+ 角色 + 状态，查询 / 重置；筛选无结果时空态说明原因。

## 2. 角色管理（/system/roles）

### 2.1 页面目标
一个角色 = 一组功能权限（菜单 / 页面 / 操作级勾选）+ 一个数据权限范围；提供新增 / 编辑 / 启停用 / 删除 / 分配权限。

### 2.2 预置角色（种子）
| 角色 | 数据范围 | 定位 |
|------|----------|------|
| 系统管理员 SYS_ADMIN | 全部 | 基础配置全部操作权限（内置，不可删除） |
| 设备管理员 DEVICE_ADMIN | 本部门及以下 | 台账 / 报警规则 / 维修派工 / 备件 |
| 维修工程师 REPAIR_ENG | 本部门 | 接单 / 执行 / 验收，只读台账 |
| 点检保养专员 INSPECTOR | 本部门及以下 | 点检 / 保养 / 巡检执行与报修 |
| 报表分析员 ANALYST | 全部 | 报表中心只读 + 导出 |
| 只读访客 VIEWER | 仅本人 | 总览 / 实时监控只读 |

### 2.3 字段与校验
| 字段 | 规则 |
|------|------|
| 角色编码 | 大写字母开头，3-30 位大写/数字/下划线，全局唯一，创建后不可修改 |
| 数据权限范围 | 全部 / 本部门及以下 / 本部门 / 仅本人（按组织机构树过滤） |
| 已分配用户 | 引用计数（从用户管理推导），角色页不允许直接删人 |

### 2.4 操作规则
1. **分配权限**：功能权限树弹窗勾选（菜单级 `menu:*` + 基础配置操作级 `perm:system:*`）；保存后用户**下次进入页面时刷新生效**。
2. **删除**：已分配用户的角色不允许删除，须先在用户管理移除；二次确认。
3. **停用**：已分配用户保留绑定，对应功能权限不再生效。
4. 新增角色默认无任何功能权限，创建成功提示进入「分配权限」。

## 3. 组织机构（/system/org）

### 3.1 页面目标
左树右表：左侧部门树（公司 → 部门 → 科室 / 车间）增删改；右侧展示所选部门的部门人员（支持「含子部门」开关）。部门树是数据权限（本部门及以下）和业务归属（使用部门 / 责任部门）的唯一组织口径。

### 3.2 部门规则
1. **新增**：必选上级部门 + 部门名称；**同级同名部门不允许创建**；显示排序按序号升序。
2. **编辑**：部门重命名时同步刷新子孙部门路径与人员路径；不允许把自己或子孙部门选为上级（防环）。
3. **删除**：存在子部门或人员时禁止删除并提示数量；**根组织（公司）不允许删除 / 停用**。
4. **停用**：停用部门不允许新增人员，人员与历史业务数据不受影响。

### 3.3 部门人员
1. 人员列表 = 用户管理中 deptPath 前缀匹配的账号（含子部门开关控制是否下钻）。
2. **新增人员**（快捷新增）：只录基础信息（工号 / 姓名 / 账号 / 部门 / 手机号）并挂部门；角色、密码等完整账号管理在用户管理页维护。
3. 人员完整编辑入口统一收敛到用户管理，组织机构页不做人员编辑 / 删除（避免两处口径）。

## 4. 字典管理（/system/dict）

### 4.1 页面目标
系统级枚举字典两级结构（字典类型 → 字典项），业务下拉 / 状态标签 / 报表口径统一取数于此，避免页面硬编码枚举。预置类型：设备运行状态、报警级别、报修来源、用户状态、数据权限范围、登录结果（种子口径与运行监测状态轴一致）。

### 4.2 字段与校验
| 字段 | 规则 |
|------|------|
| 字典编码 | 小写字母开头，2-30 位，全局唯一，创建后不可修改 |
| 字典标签 | 业务显示文字；**同一类型内唯一** |
| 键值 | 业务存储编码；**同一类型内唯一**，保存后不建议修改 |
| 排序 | 字典项在下拉中的显示顺序 |

### 4.3 操作规则
1. **删除类型**：类型下存在字典项时禁止删除，须先清空字典项。
2. **停用字典项**：业务侧新增数据不再提供该选项，**历史数据不受影响**。
3. **删除字典项**：二次确认；已被引用的项删除后历史记录按原标签显示。

## 5. 日志管理（/system/logs）

### 5.1 页面目标
两个 Tabs 视图：**登录日志**（每次登录的成败与失败原因）+ **系统操作日志**（关键业务动作追溯），运维排查与操作审计的统一入口。

### 5.2 登录日志
字段：日志编号、登录时间、用户 / 账号 / 部门、IP、登录地点（按 IP 段推导：厂区办公网 / 车间终端 / 外网 VPN / 机房运维网）、浏览器、操作系统、结果（成功 / 失败）、描述（失败原因：密码错误次数 / 账号停用 / 锁定）。Tab 标签实时显示失败条数。

### 5.3 系统操作日志
1. 记录范围：新增 / 修改 / 删除 / 导入 / 导出 / **状态流转**（派工、完结等）/ **分配权限 / 重置密码**（基础配置敏感动作）。
2. 字段：日志编号、操作时间、操作人 / 部门、所属模块、操作类型（不同 Tag 色）、操作内容（含对象编号与关键变更，如「主轴温度上限 75℃ → 78℃」）、IP、结果、耗时（ms，空值 `--`）。

### 5.4 规则
1. 日志由系统自动写入，**不提供人工新增 / 编辑**。
2. 查询：登录日志（用户 / 结果 / 关键词），操作日志（模块 / 操作人 / 结果 / 关键词），均支持导出。
3. **清空**：仅系统管理员，二次确认并建议先导出留档。
4. 日志保留策略建议：登录日志 ≥ 180 天，操作日志 ≥ 365 天（后端落地时按此配置归档任务）。

## 6. 通用交互与实现口径

1. 布局遵照 docs/后台UI设计与交互规范.md：筛选卡在上，新增 / 批量 / 导入 / 导出在列表卡左上工具栏；行级操作固定右侧（编辑 → 敏感操作 → 启停用 → 删除），破坏性操作 Popconfirm 二次确认。
2. 弹窗表单 vertical 布局，全局两列网格自动生效；编号类字段自动生成并禁用编辑。
3. 状态一律统一 StatusTag，空值一律 `--`，空态用 EmptyState 说明原因。
4. 前端演示模式：数据种子 `src/data/systemConfig.js`（时间口径 2026-09-16 前后，禁用 Date.now()），增删改页面内生效、刷新恢复，不写入 DemoStore；提示文案按规范仅在涉及写入的提交提示带「演示模式」说明。
5. 需求细则同步维护在 `src/specs/pageSpecs.jsx`（铁律 3），本文档为模块级需求交付文档。
