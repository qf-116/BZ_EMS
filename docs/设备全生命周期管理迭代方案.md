# 设备全生命周期管理迭代方案

## 1. 结论先行

当前标准版已经覆盖“设备启用后的运行管理”：设备台账、联网监测、报警、点检/巡检/保养、维修、备件、OEE 和报表。缺口集中在“设备形成前”和“设备退出后”，以及资产状态变更的审批和留痕。

本次迭代建议新增一个独立的 **设备全生命周期管理域**，通过业务单据驱动设备状态，不建议只在设备台账中直接编辑生命周期状态。

目标闭环：

```text
需求/年度计划 → 采购申请 → 采购执行 → 到货/入厂 → 安装 → 调试 → 验收
      → 建立资产台账/启用 → 运行维护（现有模块）
      → 调拨/变更/停用/闲置 → 再启用
      → 报废申请 → 技术鉴定/审批 → 拆除处置 → 财务核销/归档
```

产品边界建议：系统负责设备业务流程、资产主数据、审批、履历、附件和状态联动；采购订单、合同付款、固定资产折旧等已有 ERP/财务系统负责的内容，以接口引用和关键字段快照为主，避免重复建设采购或财务 ERP。

## 2. 现有系统基线与缺口

### 2.1 已有能力

- 设备资产：设备台账、设备详情、综合文档库、基础类型配置。
- 现场运营：点检、保养、巡检、维修、备件。
- 运行数字化：联网配置、实时监控、报警、OEE、停机事实、程序比对。
- 管理分析：运行、生产、维修、报警、备件、点巡保养等报表。
- 状态层已经使用 DemoStore、reducer、domain 和 selector 组织业务闭环，适合继续扩展生命周期状态机。

### 2.2 关键缺口

1. **缺少设备需求和采购前置过程**：没有需求申请、预算、技术规格、采购审批、供应商和采购单关联。
2. **缺少到货/入厂业务**：无法记录到货批次、设备序列号、开箱检查、资料齐套、缺陷和退货/补货。
3. **缺少安装调试过程**：没有现场条件确认、安装计划、调试项目、试运行数据、问题整改和厂家服务记录。
4. **缺少正式验收**：无法区分技术验收、安全验收、性能验收、资料验收和最终验收，也没有“条件通过/整改后复验”。
5. **缺少资产启用机制**：采购日期、启用日期目前是台账字段，不能由验收通过自动形成资产并触发二维码、责任人、位置、保修和监测配置。
6. **缺少资产变更履历**：调拨、移位、换责任人、改造、扩展、拆分/合并、借用/外送等变化无法审批和追溯。
7. **缺少闲置/停用闭环**：没有闲置原因、保管措施、定期复核、再启用条件和闲置资产盘活过程。
8. **缺少报废/处置闭环**：没有报废技术鉴定、残值、环保/安全处理、拆除、处置去向、财务核销和最终归档。
9. **缺少统一生命周期履历**：现有设备详情应增加从采购到处置的时间线，而不是把信息分散在多个列表页面。
10. **缺少流程级约束**：当前台账编辑是演示交互，状态可以直接修改；正式开发后必须改为“动作 + 前置校验 + 审批 + 状态变更 + 审计”。

## 3. 目标业务架构

### 3.1 建议菜单

在现有“设备资产”下新增：

1. 设备生命周期总览
2. 设备需求与采购
3. 到货/入厂管理
4. 安装调试管理
5. 设备验收管理
6. 设备变更管理
7. 闲置/停用管理
8. 报废处置管理
9. 生命周期报表

现有“设备台账”和“综合文档库”保留，并在设备详情中增加“生命周期履历、采购信息、验收资料、变更记录、闲置/报废记录”等 Tab。

### 3.2 角色建议

| 角色 | 主要职责 |
|---|---|
| 需求部门/使用部门 | 提出设备需求、确认技术规格、参与试运行和使用验收 |
| 设备管理员 | 编码、资产建档、安装调试组织、验收组织、状态维护 |
| 采购人员 | 供应商、询比价、采购单/合同关联、到货计划 |
| 仓储/门卫 | 到货登记、入厂、暂存、开箱和数量核对 |
| 厂家/服务商 | 安装、调试、培训、整改、保修服务 |
| 安全/质量人员 | 安全、特种设备、质量和合规验收 |
| 财务人员 | 资产价值、资本化日期、折旧/核销接口确认 |
| 部门负责人/分管领导 | 采购、变更、闲置、报废审批 |
| 系统管理员 | 流程模板、编号规则、主数据和接口配置 |

权限与审计继续复用宿主平台能力；本系统需提供业务单据的审批节点、候选角色和数据范围配置。

## 4. 核心流程与状态机

### 4.1 设备购置到启用

```text
草稿 → 待审批 → 已批准 → 采购中 → 待到货 → 已到货/入厂
→ 安装中 → 调试中 → 待验收 → 整改中 → 复验
→ 验收通过 → 已建档 → 已启用
```

异常分支：审批驳回、采购取消、部分到货、到货不合格、退货、调试失败、验收不通过、条件通过待整改。

### 4.2 运行中的资产状态变化

```text
在用 → 调拨中 → 在用
在用 → 变更审批 → 在用
在用 → 闲置申请 → 闲置
闲置 → 再启用申请 → 调试/点检 → 在用
在用/闲置/停用 → 报废申请 → 鉴定 → 待处置 → 已处置 → 已归档
```

### 4.3 不要把所有状态放进一个字段

建议拆成四个状态轴，避免与现有实时状态和维修状态混淆：

- `assetStage`：采购中、入厂、安装、调试、待验收、已建档、已归档等资产阶段。
- `useStatus`：未启用、在用、闲置、停用、报废申请、已报废。
- `operationStatus`：运行、待机、故障、停机、离线等运行状态，沿用现有监测域。
- `custodyStatus`：在厂、暂存、外送维修、借用、处置中等保管状态。

兼容现有页面时，可先保留 `lifecycleStatus` 作为展示映射字段，但所有新流程应以四个状态轴为事实来源。只有“在用”且联网配置有效的设备才进入实时监测和 OEE 统计。

## 5. 新增功能需求

### 5.1 设备需求与采购

- 需求申请：需求部门、设备类别、数量、技术规格、产能/质量目标、预算、期望到货日期、安装位置、需求原因。
- 技术规格模板：按设备类型配置必填参数、附件清单和验收指标模板。
- 采购审批：按金额、设备类型、组织层级匹配审批路径；支持驳回、撤回、转审和加签。
- 采购执行：供应商、报价/比选记录、采购单号、合同号、订单数量、含税金额、计划交期、质保期。
- 到货计划：计划到货、分批到货、延期、供应商交付承诺和提醒。
- 外部系统关联：保存 ERP 采购单、合同、供应商和财务项目编号；不要在本系统重复维护完整付款账。

### 5.2 到货/入厂管理

- 到货通知和入厂登记：采购单、供应商、车辆/人员、到货时间、箱数、设备序列号。
- 开箱检查：外观、铭牌、数量、随机附件、说明书、合格证、校准证书、备件和工具。
- 到货质量：合格、部分缺陷、待处理、不合格、退货；支持照片和问题单。
- 临时状态：到货设备在正式验收前不得进入“在用”或 OEE。
- 批量到货：一张采购单支持多台设备、多批次、部分收货和差异处理。

### 5.3 安装与调试

- 安装条件确认：基础、供电、气源、水路、网络、安全防护、环境和吊装条件。
- 安装任务：计划、负责人、厂家、开始/结束时间、现场照片、施工记录。
- 调试方案：空载、负载、精度、节拍、联机、报警、安全联锁、能耗等项目。
- 试运行记录：试运行时长、产量、良率、关键参数、异常、停机和整改措施。
- 问题闭环：问题登记、责任方、计划完成日、整改证据、复验结果。
- 培训交接：操作、维修、安全培训和培训签到。

### 5.4 设备验收

- 验收申请：由设备管理员发起，自动带出采购、到货、调试和技术规格资料。
- 验收清单：技术、性能、质量、安全、环保、资料、备件、培训、外观和资产信息。
- 结果：通过、条件通过、整改后复验、不通过、退货。
- 签署与留痕：验收人、使用部门、设备部、质量/安全、厂家、验收时间和意见。
- 验收通过动作：生成/激活设备资产、确认启用日期、启动质保、生成二维码、绑定位置/责任人、可选触发联网配置和点巡保养计划。
- 验收不通过动作：资产不得启用；保留问题、整改和复验记录。

### 5.5 资产建档与启用

- 自动生成设备编码、资产编号或接收外部系统编码。
- 完善基本档案：序列号、制造号、品牌型号、原值、安装日期、启用日期、质保起止、供应商、合同/采购单、位置、责任人。
- 打印二维码/铭牌，二维码进入设备详情和履历。
- 关联综合文档、说明书、图纸、验收单、培训记录和保修条款。
- 启用校验：必须验收通过、位置和责任人已确认、必备资料齐套；需要监测的设备还要完成 IoT 绑定。

### 5.6 设备变更管理

- 调拨：部门、车间、产线、工位、责任人变更。
- 移位：位置变更及对产线/OEE/联网配置的影响评估。
- 资产属性变更：分类、名称、型号、重要等级、OEE 资格、技术参数。
- 技术改造：改造内容、改造前后参数、费用、供应商、重新调试/验收。
- 拆分/合并：主设备、子设备、组件和父子关系。
- 外送/借用/返厂：出厂、归还、责任人、预计归还时间和保管状态。
- 规则：在维修中、报废审批中、处置中的设备，不允许直接调拨或删除；变更前后必须保留快照。

### 5.7 闲置/停用与再启用

- 闲置申请：原因、开始时间、预计闲置时长、当前价值、保管地点、封存措施、盘活建议。
- 审批校验：未完成维修/验收/借用/报废流程的设备不得进入闲置。
- 闲置保全：定期通电、润滑、防锈、环境检查、点检任务和照片。
- 闲置复核：按月/季度提醒责任人复核，继续闲置、再利用、调拨、出租或报废。
- 再启用：状态恢复前完成解封、点检、试运行、联网检查和责任人确认。

### 5.8 报废与处置

- 报废申请：技术寿命、故障频发、维修经济性、产线淘汰、安全/环保、闲置超期等原因。
- 技术鉴定：设备现状、维修价值、预计残值、可拆部件、危险物质、照片和鉴定意见。
- 多级审批：设备部、使用部门、财务、资产负责人、分管领导；金额或特种设备按规则加签。
- 处置方案：报废拆除、内部调剂、出售、回收、返厂、以旧换新、环保处理。
- 处置执行：拆除日期、承包商、称重/交接、去向、残值收入、环境和安全证明。
- 关闭条件：未关闭的维修/借用/联网绑定/库存关联必须处理；完成财务核销后才进入“已归档”。
- 禁止物理删除：报废设备及其履历只允许归档，所有业务资料长期可追溯。

### 5.9 生命周期总览、履历和报表

- 生命周期总览：按阶段显示待办、超期、金额、数量、异常和即将到期事项。
- 设备 360 履历：采购、到货、安装、调试、验收、启用、维修、保养、变更、闲置、报废、处置时间线。
- 管理指标：采购周期、到货准时率、验收一次通过率、调试周期、质保期内故障率、闲置率、闲置时长、报废周期、处置回收率、生命周期成本。
- 预警：到货延期、调试超期、验收超期、质保到期、闲置复核到期、报废审批超期、资料缺失。

## 6. 数据模型建议

### 6.1 新增业务实体

| 实体 | 关键内容 |
|---|---|
| `equipment_requests` | 需求、预算、技术规格、申请部门、审批状态 |
| `procurement_records` | 供应商、采购单/合同、金额、交期、质保、外部单号 |
| `arrival_records` | 到货批次、入厂、开箱检查、差异和质量结果 |
| `installation_tasks` | 安装计划、现场条件、负责人、厂家和施工记录 |
| `commissioning_records` | 调试方案、试运行数据、问题整改和复验 |
| `acceptance_records` | 验收清单、结论、意见、签署人、附件 |
| `asset_change_records` | 调拨、移位、改造、借用、拆分/合并的前后快照 |
| `idle_applications` | 闲置原因、保全、复核、再启用 |
| `scrap_applications` | 报废原因、鉴定、审批、处置方案 |
| `disposal_records` | 拆除、交接、去向、残值、环保和财务核销 |
| `lifecycle_events` | 所有状态变更的统一事件时间线 |
| `workflow_instances` | 审批实例、节点、意见、处理人、超时信息 |
| `attachments` | 采购、验收、调试、处置等附件元数据和版本 |

### 6.2 设备主数据建议新增字段

`assetStage`、`useStatus`、`custodyStatus`、`serialNo`、`manufacturerNo`、`supplierId`、`purchaseOrderNo`、`contractNo`、`arrivalDate`、`installationDate`、`commissioningDate`、`acceptanceDate`、`warrantyStart`、`warrantyEnd`、`originalValue`、`residualValue`、`currentLocation`、`assetSource`、`lifecycleVersion`。

现有 `buyDate`、`enableDate`、`lifecycleStatus` 保留兼容，但逐步改为由生命周期单据计算或同步，不允许用户在台账中任意覆盖事实。

## 7. 分期迭代方案

### 迭代 0：流程和技术基线（2~3 周）

目标是先把规则定死，避免页面先行导致返工。

- 确认生命周期状态轴、单据编号、组织和审批矩阵。
- 确认采购/财务/ERP 的系统边界与接口字段。
- 固化设备类型技术规格模板、验收模板、附件分类和通知规则。
- 设计 `lifecycle_events`、工作流、附件、外部单号和幂等规则。
- 完成现有设备数据盘点：哪些设备已有采购、验收、质保和位置数据。

交付物：流程蓝图、角色权限矩阵、状态机、字段字典、接口清单、迁移模板和验收用例。

### 迭代 1：购置到启用 MVP（6~8 周，最高优先级）

覆盖新设备从申请到正式入账，优先解决“设备能不能合法进入台账和运行系统”。

- 设备需求与采购申请
- 采购/合同/供应商关联
- 到货/入厂和开箱检查
- 安装与调试任务
- 验收清单、整改、复验
- 验收通过自动建档/启用
- 设备生命周期总览和工作台待办
- 设备详情生命周期履历
- 采购延期、调试超期、验收超期提醒

一期不做完整采购执行和付款管理，以 ERP/采购系统单号关联为准。

### 迭代 2：资产变更与闲置管理（4~6 周）

覆盖设备投产后的资产治理，防止台账和现场实际逐渐失真。

- 调拨、移位、责任人变更
- 技术改造及重新调试/验收
- 借用、外送、返厂和归还
- 闲置申请、审批、保全、定期复核
- 再启用检查和状态恢复
- 变更前后快照、设备位置和责任人历史
- 与维修、点检/保养、联网配置、OEE 的联动校验

### 迭代 3：报废处置和资产退出（4~6 周）

覆盖设备从报废申请到归档，形成最后一公里闭环。

- 报废申请和技术鉴定
- 多级审批、金额/设备类型规则
- 处置方案、拆除、交接和去向
- 残值、回收收入、环保/安全附件
- 财务核销接口和归档
- 报废设备监测解绑、任务关闭和历史只读
- 闲置转报废、报废转内部调剂等分支

### 迭代 4：集成和运营优化（按项目资源安排）

- ERP/采购/财务双向接口和幂等重试
- 移动端扫码、现场拍照、电子签名
- 供应商质量和质保索赔
- 生命周期成本和投资回报分析
- 资产盘点、二维码盘点差异和批量调整
- BI 主题分析和管理驾驶舱

## 8. 优先级

### P0：必须先做

- 状态机和业务单据驱动
- 采购申请、到货/入厂、安装调试、验收、启用建档
- 设备详情生命周期履历
- 闲置申请/审批/再启用
- 报废申请/鉴定/审批/处置/归档
- 附件、审批意见、操作留痕、消息提醒
- 与现有监测、维修、点巡保养、备件和 OEE 的状态联动

### P1：强烈建议

- 调拨/移位/技术改造
- 批量到货、分批验收、条件通过和复验
- 供应商履约、质保和索赔

- 生命周期 KPI 和预警报表

### P2：后续增强

- 全量采购比价、订单执行和付款协同
- 复杂固定资产折旧核算
- 生命周期成本预测和投资回报
- AI 故障/报废建议、自动估值等智能能力

## 9. 与现有系统的联动规则

1. **台账**：台账是资产主数据展示入口，新增和状态变更必须来自生命周期单据；禁止直接把“闲置/报废”作为普通编辑字段保存。
2. **监测**：只有 `useStatus=在用` 且已启用联网绑定的设备参与实时监测；闲置、停用、报废申请设备默认暂停监测和报警，保留历史数据。
3. **维修**：报废、调拨、闲置前检查是否存在维修中/待验收工单；未关闭时必须阻断或要求强制处理并留痕。
4. **点检/保养/巡检**：在用设备自动纳入计划；闲置时暂停或切换为保全计划；再启用前生成复机检查任务。
5. **备件**：报废或改造时支持设备关联备件、拆下件和可复用件处理，不能产生孤立库存流水。
6. **OEE**：非在用设备不参与 OEE；停机、闲置和计划停机的口径要与现有 OEE 规则区分。
7. **文档库**：采购、安装、调试、验收、质保和处置附件统一关联设备和生命周期单据。
8. **工作台**：新增待审批、待到货、调试超期、待验收、闲置复核、报废审批等待办。

## 10. 每期验收标准

### 迭代 1

- 一台新设备可以完成“申请→审批→采购关联→到货→安装→调试→验收→建档→启用”。
- 验收不通过时不能启用；整改后可复验，原意见和附件不丢失。
- 验收通过后能自动生成设备档案、二维码、质保起止和责任人/位置信息。
- 单据状态、设备状态、工作台待办和设备履历保持一致。

### 迭代 2

- 一台在用设备可以完成调拨、移位、责任人变更和闲置/再启用。
- 变更前后信息可追溯，监测、OEE、维修和保养联动规则生效。
- 闲置设备按周期产生复核待办，复机前必须完成检查。

### 迭代 3

- 一台设备可以完成报废申请、技术鉴定、多级审批、处置、核销和归档。
- 存在未关闭维修、借用、外送、联网绑定或库存关联时，系统能阻断或明确提示处理。
- 报废设备不能再出现在可用设备、OEE 和实时报警清单中，但历史履历和报表仍可查询。

## 11. 开发前必须确认的 10 个问题

1. 采购申请和采购订单的主系统是本系统、ERP 还是 OA？
2. 设备到货是否经过仓库，还是直接入厂安装？“入厂登记”和“资产入账”是否必须分开？
3. 一张采购单是否会对应多台设备、成套设备和子设备？是否需要父子资产关系？
4. 验收是否需要技术、质量、安全、使用部门和财务分别签署？
5. “条件通过”是否允许先使用，还是必须整改完成后才能启用？
6. 固定资产原值、资本化日期、折旧和残值由哪个系统维护？
7. 闲置多久需要复核，闲置设备是否必须转移到专用保管位置？
8. 哪些设备属于特种设备，报废/迁移是否有额外合规节点？
9. 报废处置是否涉及竞价、回收商、危险废物或环保联单？
10. 设备编码、资产编号、序列号、二维码的唯一规则是什么？

## 12. 对当前原型的落地建议

现有菜单已经在“设备资产”下预留了采购申请、到货验收、安装调试、设备变更和报废处置入口，下一轮原型可以沿用该信息架构。实现时建议新增：

- `src/domain/lifecycle.js`：生命周期状态机和前置校验。
- `src/state/actions.js` / `reducer.js`：申请、到货、调试、验收、变更、闲置、报废和处置动作。
- `src/state/selectors.js`：生命周期总览、待办、设备履历和联动状态。
- `src/data/demo/lifecycle.js`：采购、到货、调试、验收、闲置、报废演示数据。
- `src/pages/*Lifecycle*`：按迭代 1~3 增加页面。
- `src/specs/pageSpecs.jsx`：同步新增页面的字段、状态和验收口径。

第一批原型建议先做“生命周期总览、设备需求与采购、到货/入厂、安装调试、设备验收、设备详情履历”六个页面，跑通一台新设备从申请到启用的演示剧本，再扩展闲置和报废。
