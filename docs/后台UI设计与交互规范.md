# 东浩智创 · 设备管理系统 后台 UI 设计与交互规范

> 版本：v1.0（2026-09-20）
> 适用范围：设备管理系统标准版全部后台管理页面（列表页、详情页、报表页、执行页、工作台）。
> 后续新增或改版页面必须遵守本规范；与既有页面冲突时，以本规范为准逐步归一。

---

## 1. 页面整体结构

```
┌──────────────────────────────────────────────┐
│ 页面标题栏（PageHeader）                       │  ← 标题 + 副标题（数据口径/更新时间）
├──────────────────────────────────────────────┤
│ 降级提示条（DegradedBanner，仅监测类页面）      │
├──────────────────────────────────────────────┤
│ 筛选卡（可折叠为一行）                         │  ← 查询条件 + 查询/重置
├──────────────────────────────────────────────┤
│ 列表卡 ┌ 操作工具栏（左上）                    │  ← 新增/批量/导入/导出
│        ├ 表格 / 空状态                        │
│        └ 分页（右下）                         │
└──────────────────────────────────────────────┘
```

规则：

1. **页面标题栏不放业务操作按钮**。标题栏右侧只允许出现两类内容：
   - **导航类按钮**：返回列表 / 返回上级（详情页、执行页）；
   - **页面级跳转**：进入实时监控 / 进入监测大屏（工作台、总览页）。
2. **新增、批量操作、导入、导出、打印等业务操作按钮，统一放在列表区域左上**（列表卡内部、表格上方第一行），不允许放在标题栏，也不允许挤在查询按钮之后。
3. 筛选卡内只放查询条件与「查询 / 重置」，不放业务操作按钮。

## 2. 操作工具栏（列表区域左上）

标准写法（参照设备台账页）：

```jsx
<Card size="small">
  <Space wrap style={{ marginBottom: 12 }}>
    <Button type="primary" icon={<Plus size={14} />} onClick={openCreate}>新增设备</Button>
    <Button icon={<Upload size={14} />}>导入</Button>
    <Button icon={<Download size={14} />}>导出</Button>
  </Space>
  <Table ... />
</Card>
```

规则：

| # | 规则 |
|---|------|
| 2.1 | 顺序：**新增类（主操作）→ 批量操作 → 导入/导出 → 其他辅助操作**，主操作永远在最左 |
| 2.2 | 主操作（新增/办理/入库）用 `type="primary"`，其余用默认按钮；**删除禁止放在工具栏**，删除是行级操作 |
| 2.3 | 图标统一 lucide，`size={14}`，与文字间距用 Button 默认 |
| 2.4 | 工具栏与表格间距 `marginBottom: 12`；按钮多于一行时 `Space wrap` 自动换行 |
| 2.5 | 需要选中行才能用的批量操作：放在工具栏但默认禁用（`disabled={!selectedRowKeys.length}`），并提示「请先勾选数据」 |
| 2.6 | 报表页：导出按钮同样放在主内容区左上（第一个 Card 顶部或内容区首行），不放标题栏 |

## 3. 行级操作（表格操作列）

1. 固定右侧（`fixed: 'right'`），操作列必须 `onClick stopPropagation`（行点击进详情的列表必须防冒泡）。
2. 顺序：**详情 → 编辑 → 状态流转（完结/停用/提交…）→ 删除**。
3. 样式统一 `type="link" size="small"`；删除按钮加 `danger`。
4. **破坏性操作（删除、作废）和不可逆流转（完结、发布、提交）必须二次确认**（`Popconfirm`），确认弹窗说明后果（如"删除后对应生成的任务一并删除"）。
5. 操作按状态条件显示，禁止显示点了必报错的按钮：
   - 未开始：可 编辑 / 删除
   - 进行中：可 详情 / 编辑 / 完结（删除隐藏）
   - 已完成 / 已关闭：仅 详情
6. 行点击 = 进详情；操作列内点击不触发行跳转。

## 4. 查询与筛选

1. 筛选卡在列表卡上方，控件顺序：**关键词搜索 → 下拉筛选（按业务重要性）→ 查询 → 重置**。
2. 关键词搜索 `Input.Search` 宽 240，下拉宽 120–180；实时筛选的页面可不放「查询」按钮，但必须有「重置」。
3. 重置同时清空全部条件并刷新列表，不放确认弹窗。
4. 筛选条件的选项从数据推导（`[...new Set(rows.map(r => r.status))]`），不允许硬编码与数据不符的枚举。

## 5. 表格

1. 列宽：编号/单号 160–200、名称 180–220、状态 90–110、时间 150–170、操作 130–220；总宽超出容器必须 `scroll={{ x: … }}`。
2. 首列（编号）`fixed: 'left'`，操作列 `fixed: 'right'`。
3. 空值显示 `--`（禁止显示空白或 undefined）；无数据 ≠ 0，未发生的数量显示 `--` 而不是 0。
4. 空状态用统一 `EmptyState`（描述 + 原因 + 下一步动作），区分「无数据」和「筛选无结果」两种原因文案。
5. 状态一律用统一 `StatusTag`（颜色映射见组件），不允许页面内自定义状态色。
6. 分页 `pageSize: 10`，右下角显示 `共 N 条`；固定小数据集（如配置项）可 `pagination={false}`。
7. 长文本 ellipsis + Tooltip；删除线、灰色、橙色等语义色只用系统既定值（如 DELAYED #d97706）。

## 6. 新增 / 编辑弹窗（表单）

1. 布局：`layout="vertical"`；**字段较多时统一两列网格**（全局 CSS 已按 `auto-fit` 实现：弹窗内表单自动两列，字段极少自动占满）；宽度 620–920，字段多的表单用 680+。
2. 弹窗顶部用 `Alert type="info"` 说明业务规则（如"设备编码在入账节点由系统自动生成"），一条弹窗最多一条提示。
3. 编号/单号类字段：新增时自动生成并禁用编辑（`disabled`），编辑时同样禁用。
4. 日期回显必须转 dayjs 对象，提交时 `format('YYYY-MM-DD')`；**直接把字符串传给 DatePicker 会白屏**。
5. 必填规则写在 `rules`，错误文案「请输入/请选择 + 字段名」。
6. 文件上传（Upload）必须 `beforeUpload={() => false}` 阻止自动上传，取 `fileList` 中的文件名存档。
7. 提交成功用 `message.success` 说明后续动作（如"系统将按周期自动生成任务"），失败说明原因。

## 7. 详情页

1. 结构：标题栏（标题 + 返回列表）→ 信息 Descriptions（column=2 或 3，`size="small"`，bordered）→ 关联数据 Card（任务/设备明细）。
2. 标题栏可放「编辑」（打开弹窗，保存后详情即时反映），编辑字段与列表页编辑弹窗保持一致口径。
3. 单据无效/不存在时显示「未找到对象」空态（原因 + 返回列表按钮），不回退展示第一条。

## 8. 反馈与提示

1. 全局使用 `App.useApp()` 的 `message`（antd v6 静态方法不再代理主题，禁止 `message` 直接 import from 'antd'）。
2. 成功提示必须包含**结果 + 后续影响**（"已创建，系统将按周期自动生成任务"），不只写"操作成功"。
3. 演示交互统一口径：页面内生效、不写入全局快照（刷新恢复），在页面注释中标注；不向用户反复强调"演示"字样破坏代入感，仅在个别涉及数据写入的提交提示中带「演示模式」说明。

## 9. 状态与动作口径（业务规则)

1. 计划类：未开始可删除（关联任务一并删除）；进行中可提前完结（已生成任务仍可执行，计划不再生成新任务）；完结/删除均需二次确认。
2. 标准类：启用/停用即时切换并提示；停用不影响历史任务。
3. 任务类：待执行/进行中显示「执行」入口；逾期任务可补执行（标记逾期完成）；临时任务与计划生成任务在列表中区分（计划列为空显示"临时任务"）。
4. 来源类字段（如入账来源）：手工新增与系统同步用不同 Tag（default / processing），文案带来源系统名。

## 10. 代码层约束

1. 页面数据来自 `standardData.js` 演示快照，新增/编辑/删除等演示交互在页面内用 `extraRows / deletedCodes / patches` 三态落地，不写入 DemoStore。
2. 新增编号规则沿用种子前缀 + 演示日期 + 序号（如 `XJJH20260916001`、`BYRW…`），从 `meta.demoDay` 取日期，禁用 `Date.now()`。
3. 日期比较用字符串 `localeCompare` / `valueOf()`，不引入未注册的 dayjs 插件。
4. 表格列禁用含 `.` 的 `dataIndex`（antd 会按嵌套路径解析导致取值失败），从 `render` 读值。
5. 新页面必须同步更新 `specs/pageSpecs.jsx` 的页面说明。

## 附：按钮位置速查

| 按钮类型 | 位置 |
|----------|------|
| 新增 / 上传 / 导入 / 导出 / 打印 | 列表区域左上工具栏 |
| 批量操作（需勾选） | 列表区域左上工具栏，默认禁用 |
| 详情 / 编辑 / 删除 / 状态流转 | 表格操作列（固定右侧） |
| 返回列表 / 返回上级 | 页面标题栏右侧 |
| 进入大屏 / 进入实时监控 | 工作台、总览页标题栏右侧 |
| 导出（报表页） | 报表内容区左上 |
