# 设备全生命周期管理功能设计文档

> 版本：V1.1（简化流程版）  
> 修订日期：2026-09-18  
> 当前状态：当前实施依据  
> 适用产品：东浩智创设备管理系统标准版

## 1. 本次修订结论

本版本覆盖上一版复杂的“到货核验、安装、调试、技术验收”页面设计。当前只保留一个简单的流程任务，流程如下：

```text
采购入账
  → 使用板块试用确认
      ├─ 合格 → 设备办理手续入账
      └─ 不合格 → 退回采购
```

### 1.1 本次不建设的展示和流程

- 不建设“到货记录”独立页面。
- 不建设“到货核验/开箱检查”页面。
- 不建设“安装管理”页面。
- 不建设“调试与试运行”页面。
- 不建设独立的“设备技术验收”页面。
- 不建设独立的“处置执行”页面。
- 不建设“移位”变更。
- 不建设“保全”功能。

说明：设备最终入账时仍需上传验收单和设备档案资料，但它们是“设备办理手续入账”节点的附件，不再形成单独的验收业务模块。

### 1.2 附件红线范围解释

附件中红线划掉的内容不做，保留范围如下：

| 业务域 | 保留功能 | 不做功能 |
|---|---|---|
| 设备变更 | 调拨、改造、借用、外送 | 移位 |
| 闲置管理 | 闲置申请、复核、再启用 | 保全 |
| 报废管理 | 报废申请、技术鉴定、财务核销、归档 | 处置执行 |
| 资产建档/启用 | 设备手续入账、台账建档、二维码/编码 | 无额外复杂验收页面 |
| 生命周期履历 | 设备详情履历 | 不新增复杂过程页 |
| 生命周期分析 | 周期、通过率、闲置率、报废归档指标 | 不统计已取消的调试/到货过程指标 |

## 2. 建设范围与系统边界

### 2.1 本系统负责

1. 承接采购入账任务。
2. 发起使用部门试用确认。
3. 根据试用结果分流：合格进入设备办理手续入账，不合格退回采购。
4. 完成设备台账信息和设备档案资料入账。
5. 管理设备调拨、改造、借用、外送。
6. 管理设备闲置、复核和再启用。
7. 管理报废申请、技术鉴定、财务核销和归档。
8. 在设备详情展示生命周期履历和关键指标。

### 2.2 不在本系统实现

- 采购申请、询价比价、下单、付款和供应商结算。
- 仓库收货、库位和库存作业。
- 安装施工、调试项目、试运行数据和厂家施工管理。
- 独立技术验收流程。
- 报废后的拆除、出售、回收、称重、运输等处置执行。
- ERP/财务的会计凭证、折旧计算和资产核销本体。
- IoT 协议、网关和真实数据采集。
- 点检、保养、巡检的计划和执行闭环。

SRM/WMS、ERP/财务、IoT、点检/保养/巡检模块继续作为外部系统或既有模块协同。本模块不重复建设其业务。

### 2.3 采购入账来源

采购入账支持两种入口：

- **SRM/WMS/采购系统推送**：带入合同、物料、供应商和采购关联信息。
- **设备管理系统手工新增**：用于接口未覆盖、历史补录或临时业务。

两种入口使用同一个采购入账单模型和同一个流程任务，不形成两套流程。手工新增必须记录来源说明和创建人。

## 3. 角色和职责

| 角色 | 主要职责 |
|---|---|
| 采购人员 | 创建或维护采购入账信息，接收试用不合格退回，补充合同和供应商资料 |
| 使用部门 | 接收试用任务，确认设备是否满足使用要求并提交合格/不合格结论 |
| 设备管理员 | 接收合格设备，办理设备手续入账，填写台账完整信息，维护生命周期状态 |
| 部门负责人 | 按组织范围审批试用确认、调拨、闲置和报废 |
| 设备/技术负责人 | 参与改造评估、报废技术鉴定和再启用确认 |
| 财务/资产人员 | 提供资产编号、原值、核销结果或财务确认意见 |
| 系统管理员 | 配置流程节点、字段必填规则、编号规则和权限 |

关键职责分离：

- 采购入账发起人不能代替使用部门完成试用确认。
- 使用部门试用确认人不能代替设备管理员办理最终台账入账。
- 报废技术鉴定人不能代替财务核销确认人。
- 流程审批人不能代替实际执行人修改历史事实。

## 5. 生命周期流程任务

### 5.1 任务统一规则

一个设备对应一个主流程任务；一个采购入账批次包含多台设备时，任务中记录数量，并在设备手续入账节点拆分设备台账。

任务公共字段：

- 流程任务号
- 当前节点
- 业务状态
- 设备名称/型号/品牌
- 数量
- 采购人员
- 使用部门
- 设备管理员
- 创建时间、提交时间、完成时间
- 退回原因
- 附件
- 操作履历

流程状态：

```text
草稿
→ 采购入账待提交
→ 使用部门试用确认中
→ 试用合格，待设备手续入账
→ 设备已入账
```

异常分支：

```text
使用部门试用确认中
→ 试用不合格，退回采购
→ 采购补充/更换后重新提交试用
```

任务完成后，设备进入设备台账；未完成前不得出现在正式在用设备清单和正式 OEE 清单中。

### 5.2 节点一：采购入账

#### 页面用途

采购人员登记已经采购或已发货的设备基本信息，提交给使用部门试用确认。这里不做采购申请、比价、下单和付款。

#### 表单字段

| 分组 | 字段 | 必填 | 说明 |
|---|---|---:|---|
| 设备 | 设备名称 | 是 | 设备名称 |
| 设备 | 型号/规格 | 是 | 型号或规格 |
| 设备 | 数量 | 是 | 正整数 |
| 设备 | 品牌 | 是 | 品牌名称 |
| 采购 | 供应商 | 否 | 可从 SRM 带入 |
| 采购 | 采购订单号 | 否 | 外部系统引用 |
| 采购 | 合同号/合同附件 | 是 | 合同编号及文件 |
| 采购 | 发货时间 | 是 | 供应商发货时间 |
| 采购 | 采购金额 | 否 | 如采购系统可提供则带入 |
| 采购 | 预计到厂时间 | 否 | 仅作提醒，不产生到货流程 |
| 组织 | 使用部门 | 是 | 后续试用确认部门 |
| 组织 | 试用负责人 | 是 | 试用任务处理人 |
| 其他 | 备注 | 否 | 采购说明 |
| 附件 | 合同、订单或发货凭证 | 按配置 | 可多文件上传 |

#### 页面操作

- 保存草稿
- 提交试用确认
- 撤回
- 查看流程
- 查看退回原因

#### 提交校验

- 设备名称、型号、数量、品牌、发货时间、合同和使用部门不能为空。
- 数量必须大于 0。
- 合同附件缺失时按配置阻断或要求填写例外原因。
- 提交后采购核心字段只读，需撤回后修改。

#### 状态变化

```text
草稿/采购入账待提交 → 使用部门试用确认中
试用不合格退回 → 采购入账待修改
```

### 5.3 节点二：使用部门试用确认

#### 页面用途

使用部门对采购入账设备进行实际试用或使用确认，只提交结果和意见，不建设独立调试或技术验收页面。

#### 表单字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| 试用结论 | 是 | 合格/不合格 |
| 试用开始时间 | 否 | 实际试用时间 |
| 试用结束时间 | 否 | 实际试用时间 |
| 使用部门意见 | 是 | 对设备适用性的说明 |
| 主要问题 | 条件必填 | 不合格时必须填写 |
| 退回建议 | 条件必填 | 不合格时填写退回采购的建议 |
| 试用照片/记录 | 否 | 支持上传 |
| 确认人 | 系统带入 | 当前处理人 |

#### 页面操作

- 提交合格
- 提交不合格并退回采购
- 保存草稿
- 查看采购入账信息
- 查看流程轨迹

#### 处理规则

- 选择“合格”后，任务进入“试用合格，待设备手续入账”，并生成设备管理员待办。
- 选择“不合格”时，必须填写主要问题和退回建议，任务退回采购节点。
- 不合格退回不删除原始采购入账信息，保留试用意见和附件。
- 采购补充或更换设备后，可以基于原任务重新提交试用，并保留历次结果。

### 5.4 节点三：设备办理手续入账

#### 页面用途

设备管理员将试用合格设备正式纳入设备管理系统，上传验收单和档案资料，填写完整设备台账信息。

#### 表单字段

| 分组 | 字段 | 必填 | 说明 |
|---|---|---:|---|
| 资产 | 设备编码 | 系统生成/可维护 | 按编号规则生成 |
| 资产 | 资产编号 | 按财务规则 | 财务系统提供时回填 |
| 设备 | 设备名称、型号、规格 | 是 | 从采购入账带入，可补充 |
| 设备 | 品牌、制造商、序列号 | 按设备规则 | 支持批量设备逐台录入 |
| 设备 | 设备分类、重要等级 | 是 | 设备主数据 |
| 来源 | 供应商、采购订单、合同 | 是 | 关联采购入账 |
| 位置 | 工厂、车间、产线、工位 | 是 | 当前安装/使用位置 |
| 责任 | 使用部门、设备负责人、保管人 | 是 | 责任归属 |
| 时间 | 发货时间、入账时间、启用时间 | 是 | 业务日期 |
| 价值 | 原值、币种、资本化日期 | 按财务规则 | 可先留待财务回填 |
| 保障 | 质保起止、服务商、保养周期 | 否 | 设备后续管理信息 |
| 连接 | IoT 编码、OEE 资格 | 按设备规则 | 需要监测时填写 |
| 资料 | 验收单 | 是 | 作为入账附件，不形成独立验收流程 |
| 资料 | 设备档案 | 是 | 说明书、合格证、图纸等 |
| 资料 | 培训/交接资料 | 否 | 按设备类型配置 |

#### 页面操作

- 保存草稿
- 上传验收单
- 上传设备档案
- 生成设备编码
- 预览台账
- 提交入账
- 退回采购补充信息

#### 入账校验

- 必须关联“试用合格”任务。
- 台账必填字段必须完整。
- 验收单和设备档案按设备类型配置为必传。
- 设备编码、序列号、资产编号不得重复。
- 设备管理员确认使用部门、位置和责任人。

#### 入账完成动作

1. 生成或更新设备台账。
2. 写入设备编码、资产编号和完整基础资料。
3. `useStatus` 从“未启用”变为“在用”或按配置进入“试用中”。
4. 记录入账时间和生命周期事件。
5. 生成设备详情履历。
6. 按配置触发 IoT、OEE、维修、备件和点巡保养联动。

- 待补充台账资料
- 待处理资产变更
- 待复核闲置设备
- 待审批报废
- 待财务核销/归档

### 6.2 任务列表字段

| 字段 | 说明 |
|---|---|
| 任务号 | 生命周期主流程任务号 |
| 当前节点 | 采购入账、试用确认、设备手续入账等 |
| 设备信息 | 名称、型号、品牌、数量 |

## 7. 设备变更

### 7.1 保留范围

- 调拨：设备在部门、车间、产线之间转移。
- 改造：设备功能、结构、参数或产能发生变化。
- 借用：设备临时借给其他部门或单位。
- 外送：设备外送维修、返厂或外部服务。

### 7.2 不做范围

- 不做移位业务。
- 不提供单独的安装位置变更流程。
- 不将普通台账编辑包装成变更单。

### 7.3 变更申请字段

- 变更类型
- 设备编码和当前台账
- 变更前快照
- 变更原因
- 变更后部门/责任人/借用方/外送方
- 计划开始和结束时间
- 是否需要改造后重新确认
- 影响的 IoT、OEE、维修、备件和点巡保养事项
- 附件和审批意见

### 7.4 变更规则

- 变更必须形成业务单据并保留前后快照。
- 改造完成后需补充改造资料，必要时重新提交使用部门确认。
- 借用和外送必须记录预计归还时间、实际归还时间和接收确认。
- 维修中、报废审批中、已归档设备原则上不得发起调拨或改造。

## 8. 闲置、复核与再启用

### 8.1 保留范围

- 闲置申请
- 闲置状态复核
- 再启用申请

### 8.2 不做范围

- 不做保全计划、定期通电、润滑、防锈等独立功能。
- 不新增保全任务或保全费用管理。

### 8.3 闲置申请字段

- 设备和当前台账
- 闲置原因
- 闲置开始时间
- 预计闲置时长
- 当前保管地点
- 复核日期
- 盘活建议
- 附件和审批意见

### 8.4 复核与再启用

- 到期自动生成复核任务。
- 复核结论：继续闲置、再启用、调拨、转报废。
- 再启用填写使用部门、责任人、位置、启用时间和必要的使用确认意见。
- 再启用完成后恢复 `useStatus=在用`，并按统一规则恢复监测、OEE、维修和点巡保养资格。

## 9. 报废、核销与归档

### 9.1 保留范围

- 报废申请
- 技术鉴定
- 财务核销确认
- 归档

### 9.2 不做范围

- 不做处置执行、拆除、出售、回收、称重、运输和环保联单管理。
- 不在本系统维护处置去向和回收收入明细。

### 9.3 报废申请字段

- 设备编码和资产编号
- 报废原因
- 当前使用状态和运行年限
- 故障/淘汰说明
- 技术鉴定意见
- 原值、账面价值、残值（如有）
- 关联维修记录
- 申请人、部门负责人和附件

### 9.4 流程

```text
报废申请
→ 技术鉴定
→ 审批
→ 财务核销确认
→ 设备状态变更为已报废
→ 归档
```

核销未确认时不得归档；已归档设备只读保留，不进入可用设备、实时报警和正式 OEE 清单。

## 10. 状态字典

### 10.1 流程状态

| 状态 | 含义 |
|---|---|
| 采购入账待提交 | 采购人员正在填写 |
| 试用确认中 | 使用部门待处理 |
| 试用不合格退回 | 已退回采购补充/更换 |
| 待设备手续入账 | 试用合格，等待设备管理员 |
| 设备已入账 | 台账已建立 |
| 闲置 | 暂不使用，等待复核 |
| 再启用中 | 正在恢复使用 |
| 报废申请中 | 报废审批和鉴定中 |
| 已报废 | 财务核销确认后的报废状态 |
| 已归档 | 历史只读状态 |

### 10.2 运行状态联动

继续沿用现有 `operationStatus`：运行、待机、计划停机、故障停机、维修中、无数据。

继续沿用 `custodyStatus`：正常保管、借用、外送等，但不新增保全状态。

旧 `lifecycleStatus` 仅用于兼容展示，不作为可写事实源。

## 12. 与现有模块联动

- **设备台账**：只有“设备手续入账”完成后正式生成或更新台账。
- **监测和报警**：设备已入账且绑定有效监测编码后，按现有规则进入正式监测。
- **OEE**：设备已入账、在用且满足现有 OEE 配置后参与统计。
- **维修和备件**：已入账设备沿用现有维修、备件流程；报废申请中默认阻止普通维修。
- **点检/保养/巡检**：既有页面和模块必须保留；生命周期节点只通过提示或接口触发，不替代其计划执行。
- **文档库**：合同、试用记录、验收单、设备档案、变更和报废资料统一关联设备。

## 13. 权限和审计

- 采购人员只能编辑采购入账节点。
- 使用部门只能处理本部门试用确认。
- 设备管理员只能处理试用合格后的设备手续入账。
- 资产变更、闲置和报废使用审批权限和组织数据权限。
- 每次提交、退回、审批、入账、变更、复核、核销和归档写入生命周期事件。
- 流程任务支持撤回、退回和重新提交，但不得删除历史意见和附件。

## 14. 一期原型范围

一期只实现：

1. 生命周期工作台。
2. 一个统一生命周期流程任务。
3. 采购入账表单。
4. 使用部门试用确认。
5. 设备手续入账表单。
6. 设备台账生成/更新。
7. 设备详情生命周期履历。

一期不实现：

- 到货、开箱、安装、调试、技术验收独立页面。
- 移位、保全和处置执行。
- 真实 SRM/WMS/ERP/财务接口。
- 真实电子签和生产级附件存储。

## 15. 验收用例

### 15.1 主流程

1. 采购人员填写设备名称、型号、数量、品牌、发货时间、合同和使用部门。
2. 提交后任务进入使用部门试用确认。
3. 使用部门提交“合格”，任务进入设备手续入账。
4. 设备管理员上传验收单和设备档案，补全台账信息。
5. 提交后生成设备台账、设备编码和生命周期履历。

### 15.2 不合格分支

1. 使用部门提交“不合格”。
2. 系统强制填写主要问题和退回建议。
3. 任务退回采购，原始采购信息和试用记录保留。
4. 采购修改或更换设备后可重新提交试用。

### 15.3 资产治理

1. 在用设备可发起调拨、改造、借用和外送。
2. 移位入口不存在。
3. 闲置设备可发起复核和再启用，不出现保全任务。
4. 报废设备完成技术鉴定和财务核销后才能归档，不出现处置执行页面。
5. 已归档设备只读，仍可查询履历。

## 16. 开发注意事项

- 以本版本为当前功能设计依据。
- 上一版文档中的到货、安装、调试、技术验收详细章节属于历史方案，不得按其页面清单开发。
- 流程任务使用统一状态机和幂等命令，避免三个节点各自形成独立台账。
- 现有点检、保养、巡检页面必须保留。
- 设备台账、监测、报警、维修、备件、OEE 的既有功能不因本次简化而删除。
